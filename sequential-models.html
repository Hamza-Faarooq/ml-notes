Motivation

Why Feedforward Networks Fail on Sequences

Standard feedforward networks (FNNs) treat every input as independent. For images or tabular data, this is fine. But for sequential data — natural language, time-series, audio, DNA — the order and context of data matter fundamentally. Consider the sentence: "The bank by the river was flooded after the river burst its bank." Understanding the second "bank" depends on every word before it. FNNs have two fatal architectural limitations:

Fatal Flaw 1: Fixed-Size Input

An FNN requires a fixed-length input vector. To process text, you'd need to decide on a maximum window size \(W\) (say, 5 words) and slide it across the sequence. But:

  • A review might be 3 words. A novel chapter might be 3,000. You can't pad/truncate both sensibly.
  • You lose all context outside the window — the model physically cannot see a dependency between a pronoun and its antecedent 50 words back.

Fatal Flaw 2: No Parameter Sharing Across Time

Even if you fix the window size, an FNN learns separate weights for every position. The word "cat" at position 1 and "cat" at position 5 are treated as completely different features — the network must learn to recognize "cat" independently at every possible position. This is wildly inefficient and fails to generalize.

What we need: An architecture that (1) handles variable-length sequences, (2) shares parameters across all time steps, and (3) maintains a memory of what it has seen. This is the Recurrent Neural Network.
Chapter 1

The Vanilla RNN — Full Mathematical Formulation

The Core Intuition

An RNN processes a sequence step by step. At each time step \(t\), it receives the current input \(x_t\) and a hidden state \(h_{t-1}\) — a vector that encodes everything the network has seen up to time \(t-1\). This hidden state is the network's "memory." It computes a new hidden state and outputs a prediction.

Mathematical Formulation

At each time step \(t\), given input \(x_t \in \mathbb{R}^d\) and previous hidden state \(h_{t-1} \in \mathbb{R}^h\):

RNN Forward Pass — Full Equations \[ h_t = \tanh(W_{hh}\, h_{t-1} + W_{xh}\, x_t + b_h) \] \[ \hat{y}_t = \text{softmax}(W_{hy}\, h_t + b_y) \]

Every Weight Matrix — What It Does

MatrixShapeRoleIntuition
\(W_{hh}\)\(h \times h\)Hidden-to-hiddenTransforms the past memory into a form compatible with the present. This matrix is the source of all gradient pathology.
\(W_{xh}\)\(h \times d\)Input-to-hiddenProjects the current input \(x_t\) into the hidden state space.
\(W_{hy}\)\(|V| \times h\)Hidden-to-outputProjects hidden state to the output space (vocabulary \(|V|\) or target space).
\(b_h, b_y\)\(h, |V|\)Bias vectorsShift terms allowing the network to learn non-zero-mean activations.
🔑 The Crucial Point: Parameter Sharing

The matrices \(W_{hh}\), \(W_{xh}\), \(W_{hy}\) are identical at every time step — there is exactly one copy of each, shared across all \(T\) steps. This is what allows RNNs to generalize to variable-length sequences and gives them translation equivariance over time. It is also what creates the vanishing/exploding gradient problem, as we will see.

The Forward Algorithm — Step by Step

  1. 1
    Initialize: Set \(h_0 = \mathbf{0}\) (zero vector). This is the blank "memory" before seeing any input.
  2. 2
    For \(t = 1\) to \(T\): Compute \(z_t = W_{hh} h_{t-1} + W_{xh} x_t + b_h\) (linear pre-activation)
  3. 3
    Apply non-linearity: \(h_t = \tanh(z_t)\)
  4. 4
    Compute output logits: \(\theta_t = W_{hy} h_t + b_y\)
  5. 5
    Produce probability distribution: \(\hat{y}_t = \text{softmax}(\theta_t)\)
  6. 6
    Compute per-step loss: \(L_t = -\sum_k y_{t,k} \log \hat{y}_{t,k}\)
  7. 7
    Total loss: \(L = \sum_{t=1}^T L_t\)

import numpy as np

# Vanilla RNN Cell — from scratch in NumPy
class VanillaRNNCell:
    def __init__(self, d, h):
        # Xavier initialization
        self.Whh = np.random.randn(h, h) * np.sqrt(1/h)
        self.Wxh = np.random.randn(h, d) * np.sqrt(1/d)
        self.bh  = np.zeros(h)
    
    def forward(self, x_t, h_prev):
        # x_t: (d,), h_prev: (h,)
        z = self.Whh @ h_prev + self.Wxh @ x_t + self.bh
        h_t = np.tanh(z)
        return h_t, z  # store z for backward pass

Loss Function Anatomy

The Sequence Loss Function — Every Term Explained

Total Sequence Loss (Categorical Cross-Entropy over T steps) \[ L = -\sum_{t=1}^{T} \sum_{k=1}^{|V|} y_{t,k} \log \hat{y}_{t,k} \]

Every Symbol, What It Is and Why

SymbolWhat It IsIntuition
\(L\)Total loss over the whole sequenceThe single number we minimize by adjusting all weights
\(\sum_{t=1}^T\)Outer sum over time stepsSum the error at every word/token position in the sequence
\(\sum_{k=1}^{|V|}\)Inner sum over vocabularyFor each time step, consider all possible words
\(y_{t,k}\)Ground-truth label at step \(t\), vocab index \(k\)One-hot: 1 for the correct word, 0 everywhere else. Mathematically collapses the inner sum to a single term.
\(\hat{y}_{t,k}\)Model's predicted probability of word \(k\) at step \(t\)The softmax output. This is what we're trying to make as large as possible for the correct word.
\(\log \hat{y}_{t,k}\)Log of predicted probabilityIf \(\hat{y} \to 1\): \(\log(1)=0\) — perfect, no penalty. If \(\hat{y} \to 0\): \(\log(0) \to -\infty\) — infinite penalty for a confident wrong prediction.
The \(-\) signNegationMakes the loss positive (since log probs are negative). We minimize positive loss.

The Beautiful Collapse (Why One-Hot Simplifies Everything)

Because \(y_{t,k} = 1\) only for the correct word index \(k^*\) and zero everywhere else, the inner sum collapses:

\[ \sum_{k=1}^{|V|} y_{t,k} \log \hat{y}_{t,k} = 1 \cdot \log \hat{y}_{t,k^*} + 0 + 0 + \cdots = \log \hat{y}_{t,k^*} \] \[ \therefore\quad L_t = -\log\hat{y}_{t,\text{correct}} \]

At each step, the loss is simply the negative log probability of the correct word. The model is ruthlessly penalized for assigning low confidence to the right answer.

🔑 Connection to Perplexity

In NLP, we report language model quality as Perplexity (PPL): \(\text{PPL} = \exp\!\left(\frac{L}{T}\right)\). It's the exponential of average per-token cross-entropy loss. A perplexity of 50 means the model is "as confused as choosing uniformly among 50 words." Lower is better. State-of-the-art LLMs achieve single-digit perplexity on standard benchmarks.

Chapter 2

Backpropagation Through Time (BPTT) — Full Derivation

To train an RNN, we compute \(\frac{\partial L}{\partial W_{hh}}\). Because \(W_{hh}\) is shared across all time steps, its gradient is the sum of its contributions from every step. This is BPTT.

Step 1: Sum Contributions Across All Time Steps

\[ \frac{\partial L}{\partial W_{hh}} = \sum_{t=1}^{T} \frac{\partial L_t}{\partial W_{hh}} \]

Step 2: Expand Each Term — The Chain Unrolls

\(L_t\) depends on \(h_t\), which depends on \(h_{t-1}\), which depends on \(h_{t-2}\), all the way back to \(h_1\). The full derivative at step \(t\) requires backpropagating through every earlier step:

\[ \frac{\partial L_t}{\partial W_{hh}} = \sum_{k=1}^{t} \underbrace{\frac{\partial L_t}{\partial h_t}}_{\text{loss→}h_t} \cdot \underbrace{\prod_{j=k+1}^{t} \frac{\partial h_j}{\partial h_{j-1}}}_{\text{chain across time}} \cdot \underbrace{\frac{\partial h_k}{\partial W_{hh}}}_{\text{local weight grad}} \]

Step 3: The Single-Step Jacobian

Let's compute \(\frac{\partial h_j}{\partial h_{j-1}}\). From \(h_j = \tanh(W_{hh} h_{j-1} + W_{xh} x_j + b_h)\):

Single-Step Jacobian \[ \frac{\partial h_j}{\partial h_{j-1}} = W_{hh}^T \cdot \text{diag}(\tanh'(z_j)) \]

Where \(z_j = W_{hh}h_{j-1} + W_{xh}x_j + b_h\) and \(\text{diag}(\tanh'(z_j))\) is a diagonal matrix of activation derivatives. Note: \(x_j\) is treated as a constant here — when differentiating w.r.t. \(h_{j-1}\), the term \(W_{xh}x_j\) has zero derivative. This is why the input \(x_t\) has no effect on the vanishing/exploding problem — only \(W_{hh}\) drives it.

Step 4: The Compounding Product — The Danger Zone

The Product of Jacobians — Source of All Pathology \[ \prod_{j=k+1}^{t} \frac{\partial h_j}{\partial h_{j-1}} = \prod_{j=k+1}^{t} W_{hh}^T \cdot \text{diag}(\tanh'(z_j)) = (W_{hh}^T)^{t-k} \cdot \prod_{j=k+1}^{t} \text{diag}(\tanh'(z_j)) \]

We are multiplying \(W_{hh}^T\) by itself \((t-k)\) times. This is where the exponential behaviour lives.

Chapter 3

Vanishing & Exploding Gradients — Mathematical Proof

To understand exactly why the product \((W_{hh}^T)^{t-k}\) causes catastrophic failure, we apply a norm bound:

Proof: The Norm Bound

Using the matrix norm inequality \(\|AB\| \leq \|A\| \cdot \|B\|\), applied recursively to the product of Jacobians:

\[ \left\|\prod_{j=k+1}^{t} \frac{\partial h_j}{\partial h_{j-1}}\right\| \leq \prod_{j=k+1}^{t} \left\|W_{hh}^T\right\| \cdot \left\|\text{diag}(\tanh'(z_j))\right\| \]

Let \(\gamma_W\) = largest singular value (spectral norm) of \(W_{hh}\), and \(\gamma_\sigma\) = max derivative of the activation function. For \(\tanh\): \(\gamma_\sigma = 1\). Then:

\[ \left\|\prod_{j=k+1}^{t} \frac{\partial h_j}{\partial h_{j-1}}\right\| \leq (\gamma_W \cdot \gamma_\sigma)^{t-k} \]

This is a geometric series in \((t-k)\). Its fate is entirely determined by whether \(\gamma_W \gamma_\sigma\) is less than, greater than, or equal to 1.

The Vanishing Case: \(\gamma_W \gamma_\sigma < 1\)

What happens physically: Every time the gradient travels backward one time step, it gets multiplied by a number less than 1. Over \(T\) steps, this is like compound decay. Example: \(\gamma_W\gamma_\sigma = 0.9\), \(T = 50\) steps:

\[ 0.9^{50} \approx 0.0052 \]

The gradient at step \(t=1\) is 200 times smaller than the gradient at step \(t=50\). The early weights receive essentially zero update signal — the model cannot learn any dependency that spans more than a handful of steps.

Physical consequence: The model becomes a short-term memory system. It can predict "The cat sat on the ___" (mat — nearby context). But it fails completely at "The trophy that sat on the large wooden shelf in the corner of the room didn't fit in the suitcase because it was too ___" (big — the pronoun resolution requires remembering "trophy," far back).

The Exploding Case: \(\gamma_W \gamma_\sigma > 1\)

What happens physically: Every backward step multiplies by a number greater than 1. Example: \(\gamma_W\gamma_\sigma = 1.1\), \(T = 100\) steps:

\[ 1.1^{100} \approx 13{,}780 \]

The gradient at the early layers is 13,780× larger than it should be. The optimizer update step \(W \leftarrow W - \alpha \cdot g\) becomes catastrophically large — weights jump wildly across the loss landscape, completely skipping the minimum, often producing NaN within a few batches.

When Do Weights Actually Become Large Enough to Explode?

This is the physical origins question. The "perfect storm" conditions:

  1. Bad initialization: Standard \(\mathcal{N}(0,1)\) weights without scaling give spectral radius \(\approx \sqrt{h}\) (random matrix theory). For \(h=256\), that's 16 — already massively explosive.
  2. Long sequences: Even a spectral radius of 1.05 is harmless for \(T=5\) but catastrophic for \(T=100\): \(1.05^{100} \approx 131\).
  3. High-loss batches: A "shocking" sequence that contradicts everything learned → large \(L\) → large initial gradient → each backward step multiplies this already-large number by \(>1\).
  4. The feedback loop: The large gradient causes a large weight update → new weights have even larger spectral radius → even larger gradient next step → runaway.

The Fixes

ProblemFixHow It WorksLimitation
Exploding gradients Gradient Clipping \(g \leftarrow g \cdot \min\!\left(1, \frac{\tau}{\|g\|}\right)\) — rescale gradient to have norm \(\leq \tau\). Preserves direction. Heuristic. Doesn't solve fundamental architecture issue.
Both Orthogonal Initialization Initialize \(W_{hh}\) as an orthogonal matrix → spectral radius exactly 1 at start. Only fixes init; weights drift during training.
Vanishing gradients LSTM / GRU architectures Replace multiplicative recurrence with additive cell state updates. Gradient of cell state w.r.t. previous cell = \(f_t\) (learned, ~1). Not matrix multiplication. More parameters, slower per-step.
Both L2 Weight Decay Penalty \(\lambda\|W_{hh}\|^2\) in loss → optimizer constantly pulls weights toward smaller values → spectral radius stays near 1. Requires careful tuning of \(\lambda\).
Mathematical Deep Dive

Spectral Radius — The Exact Trigger for Gradient Explosion

What Is an Eigenvalue?

When a matrix \(W\) multiplies a vector \(v\), it generally rotates and scales \(v\) into a completely new direction. But for special vectors — called eigenvectors — the matrix only scales them, without changing their direction:

\[ W v = \lambda v \]

\(\lambda\) is the eigenvalue — the scaling factor for that eigenvector. If \(\lambda = 2\), the vector doubles in length. If \(\lambda = 0.5\), it halves. If \(\lambda = -1\), it flips direction.

The Spectral Radius

Definition \[ \rho(W) = \max_i |\lambda_i| \]

The spectral radius is the maximum absolute eigenvalue — the maximum "stretching power" of the matrix. No input vector can be stretched by more than \(\rho(W)\) when multiplied by \(W\).

Why Repeated Multiplication Is Dominated by the Largest Eigenvalue

When we compute \(W^n v\) (multiply by \(W\) exactly \(n\) times), by the eigendecomposition \(W = P\Lambda P^{-1}\):

\[ W^n v = P \Lambda^n P^{-1} v \]

The diagonal matrix \(\Lambda^n\) has entries \(\lambda_1^n, \lambda_2^n, \ldots\). As \(n \to \infty\), the term with the largest \(|\lambda_i|\) dominates all others. The long-run behavior is entirely determined by \(\rho(W)\).

🎯 Exact Threshold Conditions

Let \(\gamma_\sigma\) = max activation derivative (\(= 1\) for tanh, \(= 0.25\) for sigmoid):

  • Vanishing: \(\rho(W_{hh}) < \frac{1}{\gamma_\sigma}\) — e.g., for tanh: \(\rho < 1\). Gradients decay as \(\rho^T \to 0\).
  • Exploding: \(\rho(W_{hh}) > \frac{1}{\gamma_\sigma}\) — e.g., for tanh: \(\rho > 1\). Gradients grow as \(\rho^T \to \infty\).
  • Stable: \(\rho(W_{hh}) = 1\) — gradient magnitude preserved exactly. Only orthogonal matrices guarantee this.
Engineering Diagnostics

Diagnosing Gradient Problems in Production

You don't compute eigenvalues during training. You look for these symptoms:

Signs of Exploding Gradients

  • Loss → NaN: Weight overflows a 32-bit float. First sign is usually a loss spike, then NaN.
  • Loss spikes: Smooth downward trend punctuated by sudden jumps to 10× the usual value.
  • Gradient norm spikes: Monitor with torch.nn.utils.clip_grad_norm_ — if you see the gradient norm jump from 2.0 to 50,000 in one batch, you have explosion.
  • Weight values diverge: Print model weight stats each epoch — if \(\|W\|\) is growing exponentially, explosion is underway.

Signs of Vanishing Gradients

  • Early layer gradient norms near zero: Logging gradient norms layer by layer (or step by step in BPTT) — the norm at step \(t=1\) is \(10^{-7}\) while step \(t=T\) is 0.5.
  • Model fails on long-range tasks: Performs well on local context prediction but collapses on tasks requiring memory beyond ~5–10 steps.
  • Loss plateaus immediately: The model learns short patterns in the first few epochs but then completely stalls — the gradient signal for deeper patterns is dead.
  • "Dead" neurons in early layers: Activations in first-layer hidden states stop changing across training batches.

Chapter 4

Long Short-Term Memory (LSTM) — Architecture & Full Math

The LSTM (Hochreiter & Schmidhuber, 1997) was the first architecture to fundamentally solve the vanishing gradient problem. Its key innovation: introduce a Cell State \(C_t\) — a separate "memory highway" that flows through time with only additive interactions, not multiplicative ones. Additive gradient paths have derivative 1, not shrinking toward 0.

The Dual-State Architecture

An LSTM maintains two separate state vectors at each time step:

  • Cell State \(C_t \in \mathbb{R}^h\): The long-term internal memory. Flows with minimal modification. This is the gradient highway.
  • Hidden State \(h_t \in \mathbb{R}^h\): The filtered output — what the LSTM exposes to the next layer or the output head. A compressed, task-relevant summary of \(C_t\).

The Complete LSTM Equations

All Six LSTM Equations \[ f_t = \sigma(W_f [h_{t-1}, x_t] + b_f) \quad \text{Forget Gate} \] \[ i_t = \sigma(W_i [h_{t-1}, x_t] + b_i) \quad \text{Input Gate} \] \[ \tilde{C}_t = \tanh(W_C [h_{t-1}, x_t] + b_C) \quad \text{Candidate Cell State} \] \[ C_t = f_t \odot C_{t-1} + i_t \odot \tilde{C}_t \quad \text{Cell State Update (THE KEY EQUATION)} \] \[ o_t = \sigma(W_o [h_{t-1}, x_t] + b_o) \quad \text{Output Gate} \] \[ h_t = o_t \odot \tanh(C_t) \quad \text{Hidden State} \]

Notation: \([h_{t-1}, x_t]\) denotes concatenation of the two vectors. \(\odot\) is element-wise (Hadamard) product. \(\sigma\) is Sigmoid. All weight matrices are learned.

Every Gate — Exact Purpose and Intuition

Gate/StateFormulaOutput RangePhysical Role
Forget Gate \(f_t\) \(\sigma(\cdots)\) (0, 1) per element Looks at the current input and past hidden state, decides what fraction of each element of \(C_{t-1}\) to throw away. \(f_t \approx 0\): forget completely. \(f_t \approx 1\): keep perfectly. Example: when processing a new sentence, forget the previous sentence's subject.
Input Gate \(i_t\) \(\sigma(\cdots)\) (0, 1) per element Decides how much of the candidate state \(\tilde{C}_t\) to actually write into cell memory. A modulation of importance.
Candidate State \(\tilde{C}_t\) \(\tanh(\cdots)\) (-1, 1) per element The new information proposed to be written to memory. Tanh is used here (not sigmoid) because memory can increase (+) or decrease (-). Sigmoid only increases.
Cell State Update \(C_t\) \(f_t \odot C_{t-1} + i_t \odot \tilde{C}_t\) Unbounded The gradient highway. Old memory scaled by forget gate, plus new information scaled by input gate. This is a linear (additive) operation — gradients flow through the \(+\) sign with derivative 1.
Output Gate \(o_t\) \(\sigma(\cdots)\) (0, 1) per element Decides what portion of the cell state to reveal as the hidden state output \(h_t\). The cell state might contain irrelevant long-term info — output gate filters what to expose.
Hidden State \(h_t\) \(o_t \odot \tanh(C_t)\) (-1, 1) per element The filtered memory exposed to the next layer. \(\tanh(C_t)\) squashes the cell state to (-1, 1). Then \(o_t\) masks which dimensions are relevant right now.
🎯 Why Sigmoid for Gates, Tanh for Data?

A: Sigmoid outputs values in (0, 1). Multiplying any vector by a Sigmoid output is a physical valve — it keeps exactly that percentage of each dimension (0 = delete, 1 = keep all). This is the semantics of "forgetting" and "remembering." Tanh is used for the cell candidate \(\tilde{C}_t\) and the output \(\tanh(C_t)\) because: (1) memory operations should be able to both add (+) and subtract (−) from stored values — tanh allows this, sigmoid doesn't. (2) tanh bounds the values to (-1,1), preventing the cell state from diverging to ±∞ over long sequences.

The Key Proof

Why LSTM Actually Solves Vanishing Gradients

Mathematical Proof: Gradient Through Cell State

Look at the cell state update: \(C_t = f_t \odot C_{t-1} + i_t \odot \tilde{C}_t\)

The gradient of \(C_t\) w.r.t. \(C_{t-1}\):

\[ \frac{\partial C_t}{\partial C_{t-1}} = \text{diag}(f_t) \]

Chaining this over multiple timesteps (backprop through time on the cell state):

\[ \frac{\partial C_t}{\partial C_k} = \prod_{j=k+1}^{t} \text{diag}(f_j) \]

Compare this to the vanilla RNN, where the product was \(\prod (W_{hh}^T \cdot \text{diag}(\sigma'))\) — a product of potentially large or small matrices.

In the LSTM, the product is just the element-wise product of forget gate values. If the forget gate learns to stay near 1 (e.g., \(f_t \approx 0.98\) for a memory that should persist), then:

\[ \prod_{j=k+1}^{t} f_j \approx 0.98^{t-k} \]

For \(t-k = 100\): \(0.98^{100} \approx 0.13\) — still meaningful! Compare to sigmoid's \(0.25^{100} \approx 10^{-60}\) in vanilla RNNs.

The key insight: The forget gate is a learned per-element scalar, not a repeated matrix multiplication. The network can learn \(f_t \approx 1\) for information it wants to remember. The gradient doesn't decay exponentially — it decays only as fast as the network decides to forget.

Parameter Count for LSTM

An LSTM has 4 gates (\(f_t, i_t, \tilde{C}_t, o_t\)), each with input weight \(W \in \mathbb{R}^{h \times d}\), hidden weight \(U \in \mathbb{R}^{h \times h}\), and bias \(b \in \mathbb{R}^h\):

\[ \text{LSTM params} = 4 \times (h \times d + h \times h + h) = 4(hd + h^2 + h) \] 
import torch.nn as nn
import torch

# LSTM in PyTorch
lstm = nn.LSTM(

    hidden_size=512,   # h: hidden/cell state dim
    num_layers=2,      # stacked LSTM layers
    dropout=0.3,       # dropout between layers (not last)
    bidirectional=False,
    batch_first=True   # input: (batch, seq, feat)
)
x = torch.randn(32, 100, 256)   # (batch=32, seq=100, feat=256)
h0 = torch.zeros(2, 32, 512)    # (num_layers, batch, hidden)
c0 = torch.zeros(2, 32, 512)
output, (hn, cn) = lstm(x, (h0, c0))
# output: (32, 100, 512) — all hidden states across sequence
# hn: (2, 32, 512) — final hidden state, both layers
# cn: (2, 32, 512) — final cell state, both layers

# LSTM from scratch — one cell forward
class LSTMCell(nn.Module):
    def __init__(self, d, h):
        super().__init__()
        self.W = nn.Linear(d+h, 4*h)  # all 4 gates in one matrix
    def forward(self, x, h_prev, c_prev):
        gates = self.W(torch.cat([x, h_prev], dim=-1))
        f, i, g, o = gates.chunk(4, dim=-1)
        f = torch.sigmoid(f); i = torch.sigmoid(i)
        g = torch.tanh(g);    o = torch.sigmoid(o)
        c_t = f * c_prev + i * g
        h_t = o * torch.tanh(c_t)
        return h_t, c_tpython
Chapter 5

Gated Recurrent Unit (GRU) — The Streamlined Alternative

The GRU (Cho et al., 2014) was designed as a simpler, faster alternative to LSTM that achieves comparable performance. Its philosophy: eliminate the separate cell state, merge the forget and input gates into a single update gate.

GRU Equations

GRU — Three Equations \[ z_t = \sigma(W_z [h_{t-1}, x_t] + b_z) \quad \text{Update Gate} \] \[ r_t = \sigma(W_r [h_{t-1}, x_t] + b_r) \quad \text{Reset Gate} \] \[ \tilde{h}_t = \tanh(W_h [r_t \odot h_{t-1}, x_t] + b_h) \quad \text{Candidate State} \] \[ h_t = (1 - z_t) \odot h_{t-1} + z_t \odot \tilde{h}_t \quad \text{Final Update (Convex Combination)} \]

Each GRU Gate — What It Does

Gate/StateRoleWhen \(\approx 0\)When \(\approx 1\)
Update Gate \(z_t\) Controls blend between old and new memory. Simultaneously acts as both forget gate and input gate — they are coupled (unlike LSTM where they're independent). \(h_t \approx h_{t-1}\): keep old memory, ignore new input completely. \(h_t \approx \tilde{h}_t\): completely overwrite memory with new candidate.
Reset Gate \(r_t\) Controls how much of the past hidden state to use when computing the candidate \(\tilde{h}_t\). Candidate ignores past: \(\tilde{h}_t = \tanh(W_h [0, x_t])\). Effectively a new fresh start. Candidate uses full past: standard hidden state computation.
Candidate \(\tilde{h}_t\) New information to potentially write to memory, modulated by how much of the past is relevant. Blend of current input and selectively-masked past hidden state.
🔑 The Convex Combination Update

The GRU update \(h_t = (1-z_t) \odot h_{t-1} + z_t \odot \tilde{h}_t\) is a convex combination — a weighted average where the weights sum to 1. This is elegant: the update gate \(z_t\) acts as a single dial between "copy the past" (\(z_t=0\)) and "use the new candidate" (\(z_t=1\)). But notice the coupling: if \(z_t = 0.8\) (heavily new), then forgetting is 0.2 — you can't independently control how much to forget and how much to add. LSTM can forget a lot while adding very little — GRU cannot.

GRU Parameter Count

\[ \text{GRU params} = 3 \times (h \times d + h \times h + h) = 3(hd + h^2 + h) \]

GRU has exactly 25% fewer parameters than LSTM for the same hidden dimension — and consequently trains ~33% faster.

import torch.nn as nn

gru = nn.GRU(input_size=256, hidden_size=512,
             num_layers=2, batch_first=True)

# GRU from scratch
class GRUCell(nn.Module):
    def __init__(self, d, h):
        super().__init__()
        self.Wz = nn.Linear(d+h, h); self.Wr = nn.Linear(d+h, h)
        self.Wh = nn.Linear(d+h, h)
    def forward(self, x, h_prev):
        combined = torch.cat([x, h_prev], dim=-1)
        z = torch.sigmoid(self.Wz(combined))  # update gate
        r = torch.sigmoid(self.Wr(combined))  # reset gate
        h_cand = torch.tanh(self.Wh(torch.cat([x, r*h_prev], dim=-1)))
        h_t = (1-z)*h_prev + z*h_cand       # convex combination
        return h_tpython

Chapter 6

Bidirectional RNNs — Seeing the Full Context

A standard RNN at step \(t\) only sees the past: \(x_1, x_2, \ldots, x_t\). For many NLP tasks, this is insufficient. To classify the sentiment of a sentence, you need to read the whole sentence. To fill a masked word, you need both left and right context.

A Bidirectional RNN runs two independent RNNs simultaneously: a forward pass (left→right) and a backward pass (right→left). The final representation at each position concatenates both.

Full Equations Including \(x_t\)

A common source of confusion: textbooks often omit \(x_t\) from the bi-RNN equations to emphasize the directional contrast. Here are the complete formulas:

Complete Bidirectional RNN Equations \[ \overrightarrow{h}_t = \tanh\!\left(W_{\overrightarrow{h}\overrightarrow{h}}\,\overrightarrow{h}_{t-1} + W_{x\overrightarrow{h}}\,x_t + b_{\overrightarrow{h}}\right) \quad \text{(Forward: processes past + present)} \] \[ \overleftarrow{h}_t = \tanh\!\left(W_{\overleftarrow{h}\overleftarrow{h}}\,\overleftarrow{h}_{t+1} + W_{x\overleftarrow{h}}\,x_t + b_{\overleftarrow{h}}\right) \quad \text{(Backward: processes future + present)} \] \[ h_t = \left[\overrightarrow{h}_t;\,\overleftarrow{h}_t\right] \quad \text{(Concatenation at each position)} \] \[ \hat{y}_t = \text{softmax}(W_g\,h_t + b_g) \]
⚠️ Why \(x_t\) Disappears in Gradient Proofs

When computing \(\frac{\partial h_j}{\partial h_{j-1}}\), the term \(W_{xh} x_t\) is treated as a constant (we differentiate w.r.t. \(h_{j-1}\), not \(x_t\)). So \(x_t\) vanishes from the Jacobian product. This means: the input sequence has zero effect on the vanishing/exploding gradient problem. Everything is driven by the spectral radius of \(W_{hh}\). The input just shifts the pre-activation value \(z_t\) — it cannot prevent the multiplicative chain from collapsing or exploding.

Why Bi-RNN Cannot Be Used for Autoregressive Generation

The backward pass requires reading the entire sequence before computing \(\overleftarrow{h}_1\). You can't predict the next token during generation because you don't have future tokens yet. Bi-RNNs are encoder models only — they read and encode full sequences (like BERT) but cannot generate text token by token (like GPT).

# Bidirectional LSTM

Chapter 7

Deep Stacked RNNs & Architecture Variants

Multi-Layer Stacked RNNs

The hidden states of one RNN layer become the input sequence of the next. A depth-\(L\) stacked RNN:

\[ h_t^{[l]} = \text{RNN}^{[l]}\!\left(h_t^{[l-1]},\, h_{t-1}^{[l]}\right) \quad l = 1, \ldots, L \]

Layer 1 processes the raw input sequence. Layer 2 processes the sequence of hidden states from Layer 1. Each layer can learn increasingly abstract temporal patterns (similar to how CNN layers learn increasingly abstract spatial features).

Sequence-to-Sequence (Seq2Seq) Models

For tasks like machine translation, where input and output are both sequences of potentially different lengths, we use an Encoder-Decoder architecture:

  • Encoder: A stacked RNN that reads the source sentence and compresses it into a fixed-size context vector \(c = h_T^{encoder}\) (the final hidden state).
  • Decoder: A separate RNN initialized with \(c\), which generates the target sequence token by token autoregressively.
⚠️ The Information Bottleneck Problem

The context vector \(c\) must encode the entire source sequence into a fixed-size vector (e.g., 512 dimensions). For long sentences, this bottleneck loses critical information from early parts of the sentence. This is why vanilla Seq2Seq models fail on long sequences — and why the Attention Mechanism was invented as the fix.

Rapid-Fire Interview Reference — Sequential Models

Explain the vanishing gradient problem in RNNs from first principles. What is the exact mathematical condition?
The gradient of the loss w.r.t. the hidden state at step \(k\) requires the product \(\prod_{j=k+1}^{T} W_{hh}^T \cdot \text{diag}(\tanh'(z_j))\). This is the same matrix \(W_{hh}^T\) raised to power \((T-k)\). The fate of this product is determined by the spectral radius \(\rho(W_{hh})\): if \(\rho < 1\) (and \(\tanh'\) is always \(\leq 1\)), the product decays as \(\rho^{T-k} \to 0\) exponentially. Early layers receive gradient ≈ 0 and stop learning. The model can't learn dependencies beyond ~5-10 steps. The exact condition: \(\rho(W_{hh}) \cdot \gamma_\sigma < 1\) where \(\gamma_\sigma\) is the max activation derivative.
Why doesn't the input \(x_t\) affect the vanishing gradient problem?
When computing \(\frac{\partial h_j}{\partial h_{j-1}}\), we differentiate \(\tanh(W_{hh}h_{j-1} + W_{xh}x_j + b)\) with respect to \(h_{j-1}\). The term \(W_{xh}x_j\) is a constant w.r.t. \(h_{j-1}\) — its derivative is zero. So \(x_j\) entirely disappears from the Jacobian. The compounding product only contains \(W_{hh}^T\) and activation derivatives — never \(W_{xh}\) or \(x_t\). The input only shifts the pre-activation \(z_t\), affecting which regime of \(\tanh\) we're in (which changes the magnitude of \(\tanh'\)), but this is a second-order effect compared to the repeated \(W_{hh}\) multiplication.
How exactly does LSTM solve the vanishing gradient problem? Show the math.
The LSTM cell state update is \(C_t = f_t \odot C_{t-1} + i_t \odot \tilde{C}_t\). The gradient of \(C_t\) w.r.t. \(C_{t-1}\) is \(\text{diag}(f_t)\) — just the forget gate values, not a matrix multiplication. Chaining across time: \(\frac{\partial C_t}{\partial C_k} = \prod_{j=k+1}^{t} \text{diag}(f_j)\). If the network learns to keep \(f_t \approx 0.98\) for long-term memories, the product decays as \(0.98^{100} \approx 0.13\) — still meaningful, vs. sigmoid's \(0.25^{100} \approx 10^{-60}\). The critical difference: the forget gate is a learned per-element scalar, not a fixed matrix repeated multiplicatively. The network controls the decay rate by learning the forget gate values.
What is the fundamental mathematical difference between how GRU and LSTM handle the forget-input relationship?
LSTM has independent forget gate \(f_t\) and input gate \(i_t\): the network can forget a lot of old memory while adding very little new information, or vice versa. This independent control is powerful for tasks like subject-verb agreement across long parenthetical phrases. GRU uses a single update gate \(z_t\) in a convex combination: \(h_t = (1-z_t) \odot h_{t-1} + z_t \odot \tilde{h}_t\). Forgetting old memory (\(z_t \approx 1\)) is mathematically coupled to accepting new information — if you forget 80%, you must accept 80% of the new candidate. You cannot forget a lot while updating a little. For most practical tasks this coupling is harmless, but it's a fundamental architectural constraint that can hurt on tasks requiring very selective memory management.
Why can a Bidirectional RNN not be used for text generation?
Autoregressive text generation requires predicting token \(t+1\) having seen only tokens \(1, \ldots, t\) — the future doesn't exist yet. The backward pass of a Bi-RNN processes the sequence right-to-left and requires the entire sequence to be available before computing \(\overleftarrow{h}_1\). At generation time, you're producing tokens one by one — you don't have the future tokens needed to run the backward pass. Bi-RNNs are encoder-only architectures (like BERT's foundation), designed for understanding/encoding full sequences. Uni-directional decoder RNNs (or Transformers with causal masking) are used for generation.
What are the physical "perfect storm" conditions that cause gradient explosion?
Three necessary conditions: (1) Spectral radius > 1 — usually from standard \(\mathcal{N}(0,1)\) weight initialization where \(\rho(W_{hh}) \approx \sqrt{h}\). For \(h=256\), that's 16. Fix: Orthogonal initialization sets \(\rho = 1\) by construction. (2) Long sequences — even \(\rho=1.05\) is harmless at \(T=5\) but catastrophic at \(T=100\): \(1.05^{100} \approx 131\). (3) High-loss batches — an outlier sequence that contradicts learned knowledge creates large initial \(\frac{\partial L}{\partial h_T}\), which gets amplified by each backward step. The feedback loop: large gradient → large weight update → larger spectral radius → even larger gradient. Fixes: gradient clipping (safety valve), orthogonal init (prevents the problem starting), L2 regularization (keeps weights small during training).
If you could only pick one between GRU and LSTM for a new project, how do you decide?
The decision matrix: (1) Dataset size — if <50K sequences, use GRU. Fewer parameters → less overfitting, faster convergence. (2) Sequence length — if sequences routinely exceed 200 steps and the task requires long-range memory (e.g., co-reference resolution across paragraphs), lean toward LSTM. The decoupled cell state is a stronger gradient highway. (3) Compute budget — GRU trains 25–30% faster for same hidden dim. If training budget is limited, GRU gets you more experiments. (4) Task structure — if you need to independently control "how much to forget" vs "how much to add," LSTM's architectural flexibility matters. For standard tasks (sentiment, NER, language modeling), they're empirically roughly equivalent. My default starting point: GRU first (fast iteration), switch to LSTM if performance plateaus on long-range tasks.
What is the information bottleneck problem in Seq2Seq models and how does attention solve it?
A Seq2Seq encoder compresses an entire variable-length source sequence into one fixed-size vector \(c = h_T\) (typically 512 or 1024 dimensions). For a 50-word sentence, this one vector must encode all semantic, syntactic, and positional information. Early words' information is increasingly diluted by later updates — the RNN effectively forgets them. The decoder must generate an entire translation from this single bottleneck vector. Attention (Bahdanau, 2015) removes the bottleneck: instead of a single \(c\), the decoder has access to all encoder hidden states \(\{h_1^{enc}, \ldots, h_T^{enc}\}\). At each decoder step \(t\), it computes attention scores \(\alpha_{ts} = \text{softmax}(f(h_t^{dec}, h_s^{enc}))\) and uses a weighted sum \(c_t = \sum_s \alpha_{ts} h_s^{enc}\) as the context. The model learns to "attend to" the most relevant source positions at each generation step, completely bypassing the bottleneck.
