Chapter 01
Missing Values
MCAR · MAR · MNAR — detection, strategy, and when to impute vs. drop

Missing data is not random noise you can ignore. The mechanism behind missingness fundamentally changes which strategy is valid. Choosing wrong leads to biased models with false confidence.

1.1 The Three Mechanisms of Missingness
MCARMissing Completely At Random

Definition: Probability of missingness is unrelated to any variable — observed or unobserved. Like a random equipment malfunction that corrupts 3% of sensor readings regardless of what the sensor was measuring.
Test: Little's MCAR Test (chi-squared). Split data into missing/observed groups on each variable — if no significant differences, it's MCAR.
Implication: Any imputation strategy is unbiased. You can even do listwise deletion without bias (just lose statistical power).

MARMissing At Random

Definition: Missingness depends on observed variables, not the missing variable itself. E.g., older patients are less likely to report income — missingness in "income" depends on "age" (observed), not on the income value itself.
Implication: Valid to impute using other observed features. Multiple Imputation (MICE) or model-based imputation are appropriate.

MNARMissing Not At Random

Definition: Missingness depends on the missing value itself. E.g., high earners don't report income precisely because it's high. The very fact of missingness is informative!
Implication: Standard imputation is biased. Best approach: create a binary indicator feature income_is_missing and let the model learn the signal in the missingness itself. Domain knowledge essential.

If you compute mean(age) on all 10,000 rows including test data, your test set is "leaking" information about the training distribution. Always: fit imputer on train, transform both train and test. 🎯 Interview Q&A — Missing Values
You have a feature where 40% of values are missing. A colleague says to just fill with the mean. What questions would you ask first?
Five questions: (1) Mechanism: Is it MCAR/MAR/MNAR? If MNAR, filling with mean destroys the signal in the missingness. (2) Is missingness correlated with the target? — if yes, create a binary "is_missing" feature regardless. (3) What does the domain say? — 40% missing "income" in a medical dataset may mean the patients declined to answer (MNAR signal: wealthy or poor). (4) What other features correlate with this one? — if strongly correlated features exist, KNN or MICE will outperform mean. (5) Model sensitivity: Tree-based models (XGBoost, LightGBM) can handle NaN natively — sometimes the best imputation is none.
Why is MICE (Multiple Imputation by Chained Equations) more powerful than mean imputation?
Mean imputation replaces every missing value of a feature with the same number (the mean), collapsing its entire distribution into a single point. This artificially reduces variance and destroys correlations between features. MICE (IterativeImputer in sklearn) models each feature with missing values as a function of all other features. It runs iteratively: impute feature 1 using 2,3,4,5; impute feature 2 using 1,3,4,5; repeat until convergence. The imputed values respect the multivariate correlation structure of the data. The "Multiple" in MICE means it generates several imputed datasets, runs the analysis on each, and pools results — properly propagating imputation uncertainty. For MAR data, MICE gives approximately unbiased parameter estimates with correct standard errors; mean imputation underestimates standard errors, leading to spuriously significant results.

2.1 Detection Methods
IQR Method
Interquartile Range Rule
IQR = Q3 - Q1 Lower = Q1 - 1.5 × IQR Upper = Q3 + 1.5 × IQR x is outlier if x < Lower or x > Upper Tukey (1977): 1.5×IQR ≈ 2.7σ for normal data Extreme outlier: use 3×IQR fence
Z-Score Method
Standard Score
z_i = (x_i - μ) / σ |z| > 3 → outlier (~0.3% of normal data) |z| > 2.5 → moderate outlier Assumption: data is approximately normal. Use Modified Z-Score for small samples: M_i = 0.6745 × (x_i - median) / MAD

Python — Outlier Detection & Treatment
import numpy as np
from sklearn.ensemble import IsolationForest
from scipy import stats

Q1 = df['feature'].quantile(0.25)
Q3 = df['feature'].quantile(0.75)
IQR = Q3 - Q1
lower, upper = Q1 - 1.5*IQR, Q3 + 1.5*IQR
outliers = df[(df['feature'] < lower) | (df['feature'] > upper)]

# --- Treatment 1: Remove ---

Interview Trap: Never Auto-Remove Outliers An interviewer might ask: "You see a salary of $10,000,000 in your dataset. Do you remove it?" Wrong answer: "Yes, it's an outlier." Right answer: "It depends. Is this a dataset of startup founders? Then $10M is valid data — the most important data points. Is it a data entry error (e.g., an extra zero)? Then yes. The correct first step is always: understand why the outlier exists before deciding what to do.
🎯 Interview Q&A — Outliers
Your linear regression model is performing poorly. You suspect outliers. How do you diagnose and fix this systematically?
Systematic diagnosis: (1) Plot Cook's Distance — measures how much the regression coefficients change when that observation is removed. Points with Cook's D > 4/n are highly influential. (2) Plot residuals vs fitted values — outliers appear as extreme residuals. (3) Plot Q-Q plot of residuals — deviation from the diagonal indicates non-normality from outliers. Fix options in order of preference: (a) Winsorize at 1st/99th percentile to cap without losing data. (b) Log or Box-Cox transform the target or skewed predictors — often eliminates the "outlier problem" entirely. (c) Switch to a robust regression method: Huber loss, RANSAC, or Theil-Sen estimator — these are inherently resistant to outliers. (d) If the outlier is a data error, remove it.
What is the difference between Isolation Forest and LOF? When would you use each?
Isolation Forest works globally: it randomly partitions features and measures how quickly each point gets isolated. Anomalies require fewer splits (shorter average path length in the forest). It's O(n log n), handles high dimensions well, and is insensitive to which density the point is in. LOF (Local Outlier Factor) works locally: it compares each point's local density to its k-neighbors' densities. A point with much lower local density than its neighbors is an anomaly. It's O(n²) and sensitive to the k hyperparameter. Use Isolation Forest for: large datasets (>50K rows), high-dimensional data (>10 features), global anomalies. Use LOF for: small datasets, data with multiple clusters of varying density (LOF detects local anomalies that IF misses — a point in a sparse region of a dense neighborhood).

Chapter 03
Scaling, Normalization & Standardization
Four methods, when to use each, and which models actually need them

Unscaled features cause two classes of problems: (1) Optimization problems — gradient descent takes oscillating steps when features have very different scales. (2) Distance problems — KNN/SVM will be dominated by features with large magnitude regardless of their actual importance.

3.1 The Four Scaling Methods
All Four Formulas Side by Side
Min-Max (Normalization): x' = (x - x_min) / (x_max - x_min) → [0, 1] Variant with range [a,b]: x' = a + (x - x_min)(b-a) / (x_max - x_min) Standardization (Z-score): x' = (x - μ) / σ → mean=0, std=1 Range: theoretically (-∞, +∞) Robust Scaling: x' = (x - median) / IQR → centered, IQR=1 Best when: outliers present Max-Abs Scaling: x' = x / max(|x|) → [-1, 1] Best when: data is already centered (sparse matrices)

3.2 Normalization vs Standardization — The Important Distinction
📝
Terminology Confusion Warning In ML, "normalization" is used in two completely different ways: (1) Feature scaling to [0,1] via Min-Max — column-wise operation. (2) L1/L2 normalization of a sample vector so it has unit norm — row-wise operation. In sklearn: MinMaxScaler = meaning (1), Normalizer = meaning (2). Always clarify which the interviewer means.
L1 vs L2 Normalization (Row-wise)
L1 Normalize: x' = x / ||x||₁ where ||x||₁ = Σ|x_i| After: Σ|x'_i| = 1 (sum of absolute values = 1) Use: text classification (TF-IDF rows), Manhattan distance L2 Normalize: x' = x / ||x||₂ where ||x||₂ = √(Σx_i²) After: ||x'||₂ = 1 (unit sphere) Use: cosine similarity, before dot-product operations
MethodModels That Require ItModels Immune To It
Any scalingKNN, SVM, PCA, K-Means, Neural Networks, Logistic Reg, ElasticNetDecision Trees, Random Forest, XGBoost, LightGBM, Naive Bayes
Standardization preferredLinear/Logistic Regression, SVMs, PCA, LDA, anything with regularization—
Min-Max preferredNeural Networks (when you want [0,1] activations), image pixel values—

🎯 Interview Q&A — Scaling
You're training a neural network. Should you standardize or min-max scale? Does it matter?
Both work, with practical differences. Standardization (z-score) is generally preferred for deep learning because: (1) Batch Normalization layers internally renormalize, so the absolute input scale matters less than having mean≈0 and std≈1 to start. (2) With ReLU activations, a feature scaled to [0,1] means roughly half the pre-activation values are positive (active) — reasonable. With standardization, ~68% are in [-1,1] which also works well. Min-Max to [0,1] can be problematic if outliers exist — the outlier gets value ≈1.0 and compresses all other values into a tiny range near 0. In practice: standardize first. For image pixels (0-255), normalize to [0,1] or [-1,1] is standard. The most important thing: be consistent between train and test.
Why don't tree-based models (Random Forest, XGBoost) need feature scaling?
Decision trees split features on threshold values: "Is feature X > 5.3?" The only thing that matters is the relative ordering of values within a feature, not their magnitude. Scaling transforms values but preserves order: if x₁ < x₂ before scaling, then x'₁ < x'₂ after scaling. So the split threshold changes (from 5.3 to, say, 0.42 after scaling), but the same data points end up in the same leaf. The tree structure is identical. XGBoost, LightGBM, CatBoost — all tree ensembles — are completely scale-invariant for the same reason. However, scaling can help tree-based models indirectly: if you're using L1/L2 regularization on the leaf weights, unscaled features with different magnitudes can affect the regularization term unevenly.

4.2 One-Hot Encoding — In Depth

The standard for nominal (unordered) categories with low-to-medium cardinality (<50 categories).

One-Hot — sklearn vs pandas

🔥
The Cardinality Explosion Problem One-hot encoding a feature with 10,000 unique values (like zip codes or user IDs) creates 10,000 new binary columns — the "curse of dimensionality" for tree models and memory explosion for linear models. Solutions by cardinality: Low (<50): one-hot. Medium (50–500): target encoding, binary encoding. High (>500): hashing trick, embeddings (neural networks), frequency encoding.
4.3 Target Encoding — The Leakage Danger

Target encoding replaces each category with the mean of the target variable for that category. Powerful, compact (1 column), and naturally handles high-cardinality. But naively done, it causes catastrophic data leakage.

Target Encoding — Wrong vs Right
# ❌ WRONG: uses entire dataset including target row
df['city_enc'] = df.groupby('city')['target'].transform('mean')
# Row "NYC, target=1" encodes NYC using 1 itself → perfect leakage

# ✅ CORRECT: use category_encoders with cross-validation
from category_encoders import TargetEncoder
enc = TargetEncoder(cols=['city'], smoothing=1.0)
X_train_enc = enc.fit_transform(X_train, y_train)  # leave-one-out internally
X_test_enc  = enc.transform(X_test)

# ✅ ALSO CORRECT: sklearn 1.3+ TargetEncoder with cross-fitting
from sklearn.preprocessing import TargetEncoder
enc = TargetEncoder(cv=5, smooth='auto')

# Smoothing formula (Laplace/empirical Bayes):
# enc = (n_i * mean_i + λ * global_mean) / (n_i + λ)
# n_i = count in category, λ = smoothing param
# Small categories → pulled toward global mean (regularized)

🎯 Interview Q&A — Encoding
You have a "Country" feature with 195 unique values. Which encoding would you choose for (a) Logistic Regression and (b) XGBoost?
(a) Logistic Regression: Target encoding with smoothing or binary encoding. One-hot creates 194 columns — the model can likely handle it computationally for 195 countries, but with L2 regularization, target encoding (1 compact column) will likely outperform because it uses the actual target signal rather than dummy variables which the regularizer might shrink to zero for rare countries. (b) XGBoost: Target encoding is the standard choice. XGBoost handles 1 numerical column representing target-encoded country perfectly. It naturally discovers splits that group high-target and low-target countries. Alternatively, CatBoost has built-in categorical handling that automatically does ordered target encoding with leak prevention.
What is the dummy variable trap and how does it cause problems in linear regression?
If you one-hot encode k categories into k binary columns without dropping one, you have perfect multicollinearity: the sum of all k columns always equals 1. In linear regression, the design matrix X has rank k-1 (not k), making X^TX singular — it can't be inverted to compute β = (X^TX)^{-1}X^Ty. The OLS estimator breaks down (infinitely many solutions with identical fit). Fix: always use drop='first' in OneHotEncoder or drop_first=True in pd.get_dummies. The dropped category becomes the reference level; all other coefficients are interpreted as "difference from reference". In practice, regularized regression (Ridge/Lasso) and tree models handle all k columns fine because: Ridge uses pseudo-inverse (doesn't need X^TX invertible), and trees don't solve linear systems.

5.1 Filter Methods — Mathematical Foundations
Key Statistical Tests for Feature Selection
Mutual Information (any relationship, any distribution): I(X;Y) = Σ_x Σ_y P(x,y) log[ P(x,y) / (P(x)P(y)) ] I=0: independent. Higher = more dependent. Non-parametric: captures non-linear relationships! Chi-Squared Test (categorical features vs categorical target): χ² = Σ (O_i - E_i)² / E_i O = observed frequency, E = expected if independent High χ² → feature and target are not independent ANOVA F-test (continuous features vs categorical target): F = (variance between groups) / (variance within groups) Assumes linearity. Better: use mutual_info_classif instead. Pearson Correlation (continuous-continuous, linear only): r = Cov(X,Y) / (σ_X · σ_Y) ∈ [-1, 1] |r| close to 1: strong linear relationship r = 0: no LINEAR relationship (may have non-linear!)
5.2 Lasso — The Embedded Selector

Lasso (L1 regularization) is the most elegant feature selection method because it makes selection and model fitting a single optimization problem:

Lasso Objective — Why L1 Produces Sparsity
Lasso: minimize (1/2n)||y - Xβ||² + λ||β||₁ The L1 norm: ||β||₁ = |β₁| + |β₂| + ... + |βₚ| Geometric insight: the L1 "ball" is a diamond (in 2D). The OLS solution "slides" toward the L1 constraint boundary. The diamond has corners on the axes → solution is likely at a corner → corners mean β_j = 0 for many j → AUTOMATIC SPARSITY. Compare L2 (Ridge): circle in 2D. Solutions rarely hit axis → few zeros. λ controls sparsity: λ=0: OLS (no regularization, no selection) λ→∞: all β=0 (too much regularization) Use cross-validation to find optimal λ
Python — Feature Selection Toolkit
from sklearn.feature_selection import (

🎯 Interview Q&A — Feature Selection
Why does L1 regularization produce sparse solutions while L2 does not? Prove geometrically.
Geometric proof: The OLS loss function ½||y-Xβ||² is a convex ellipse centered at the OLS solution β̂. We want to minimize loss subject to the constraint ||β|| ≤ t (equivalent to adding the regularization term). For L2 (Ridge): the constraint region is a sphere (smooth everywhere). The optimum is where the loss ellipse first touches the sphere. Since the sphere is smooth, the optimal point is typically not at an axis, so β_j ≠ 0 for most j. For L1 (Lasso): the constraint region is a diamond (absolute value = L1 ball) with sharp corners on the axes (points where all but one β_j = 0). The loss ellipse is much more likely to first touch the constraint set at one of these sharp corners, because the corners protrude outward while the interior is indented. This geometric tangency at corners forces β_j = 0 for many j, producing sparsity. Algebraically: L1's subdifferential at β_j=0 is [-1,+1], meaning the KKT conditions can be satisfied with β_j exactly 0; L2's gradient at β_j=0 is 0, meaning the OLS gradient must be exactly 0 for a zero coefficient — rarely happens.
Two features are 95% correlated with each other. How does Lasso handle this? How does Ridge?
This is the multicollinearity problem. Lasso (L1): arbitrarily picks one of the two correlated features and zeros out the other. Which one it picks is unstable — small data changes can swap the selection. The "chosen" feature gets all the coefficient mass. This makes Lasso unreliable for grouped selection of correlated features. Ridge (L2): splits the coefficient mass approximately equally between both features — each gets roughly half the total coefficient. The solution is stable but both features remain in the model. ElasticNet (L1 + L2): the best of both worlds. The L2 term groups correlated features together (keeps both), while the L1 term performs selection on the groups. Recommended whenever you suspect correlation between features (ElasticNet with alpha tuned via cross-validation).

6.1 Dimensionality Reduction as Extraction

Unlike selection (which keeps a subset of original features), extraction creates new features as functions of the original ones:

PCA vs LDA — Unsupervised vs Supervised Extraction
PCA (Unsupervised): maximize variance Find W such that variance of XW is maximized W = eigenvectors of cov(X) corresponding to top eigenvalues No class label used. Preserves global structure. Use when: dimensionality reduction for any task. LDA (Supervised): maximize class separability Maximize: (between-class scatter) / (within-class scatter) J(W) = W^T S_B W / W^T S_W W (generalized eigenvalue problem) S_B = between-class scatter matrix S_W = within-class scatter matrix Use when: you want the dimensions that best separate classes. Max components: min(k-1, p) where k=classes, p=features
6.2 Manual Feature Engineering Techniques
Python — Feature Engineering Patterns
import pandas as pd
import numpy as np
from sklearn.preprocessing import PolynomialFeatures

# 1. Date/Time Feature Extraction (rich signal source)
df['hour']        = df['timestamp'].dt.hour
df['day_of_week']  = df['timestamp'].dt.dayofweek
df['is_weekend']   = df['day_of_week'].isin([5,6]).astype(int)
df['month']        = df['timestamp'].dt.month
df['quarter']      = df['timestamp'].dt.quarter

# Cyclical encoding for periodic features (hour, month)

Cyclical Encoding — The Hour Problem If you encode hour as an integer (0-23), hour 23 and hour 0 are 23 units apart in the model's view, but only 1 hour apart in reality. Using sin/cos encoding maps the circle onto a 2D point: midnight gets (sin=0, cos=1), noon gets (sin=0, cos=-1), 6am gets (sin=1, cos=0). The Euclidean distance in (sin, cos) space correctly reflects time-of-day proximity. Apply the same trick to months (÷12), day of week (÷7), degrees (÷360).
🎯 Interview Q&A — Feature Engineering
Your model has 500 features. Describe your complete feature selection pipeline from start to finish.
Step 1 (Preprocessing): Remove features with >80% missing values and >95% constant values (VarianceThreshold). Step 2 (Filter pass): Compute mutual information between each feature and target. Drop bottom 20% — fast, model-agnostic, keeps non-linear relationships. Separately check Pearson correlation between remaining features; if two features are >0.95 correlated, keep the one with higher MI to target. Step 3 (Embedded): Train a LightGBM with built-in feature importance. Drop features with importance in the bottom 10% of the distribution. Cross-validate to ensure this doesn't hurt performance. Step 4 (Wrapper if needed): Run RFECV with the actual production model and target metric on the remaining features. Computationally expensive but maximally accurate. Step 5 (Validation): Compare test AUC/F1 at each step to ensure you're not dropping important features. Track feature count vs performance curve. Production: wrap entire pipeline in a sklearn Pipeline so all fitting happens only on train folds during cross-validation.
You're given a raw "transaction_timestamp" column. What features would you engineer from it?
At minimum: hour (cyclical sin/cos), day_of_week (cyclical sin/cos), month (cyclical sin/cos), quarter, year, is_weekend (binary), is_holiday (binary, requires holiday calendar), days_since_epoch (monotonic time trend). Advanced: recency (days since most recent transaction for that user), seasonality components (use STL decomposition on aggregated time series), time_since_last_transaction per user (inter-event time), hour×day_of_week interaction (different behavior on Friday nights vs Monday mornings). Domain-specific: for banking, is_business_hours; for e-commerce, days_before_payday; for healthcare, days_until_appointment. The timestamp itself encodes enormous signal — feature engineering quality here often differentiates good ML practitioners from great ones.
