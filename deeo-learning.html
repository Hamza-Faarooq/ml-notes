Chapter 61

The Perceptron & The Forward Pass

The Perceptron: The Ancestor (1958)

Before neural networks, there was the Perceptron — a single mathematical neuron created by Frank Rosenblatt. It takes inputs, multiplies them by weights, adds a bias, and passes the sum through a hard threshold (Heaviside step function):

Perceptron Decision Rule ŷ = 1 if W·X + b > 0, else ŷ = 0

The Perceptron Convergence Theorem

This is a formal mathematical guarantee: if the data is linearly separable, the Perceptron algorithm is guaranteed to converge and find the separating hyperplane in a finite number of steps. The bound on updates is:

Updates ≤ R² / γ² R = max norm of any training point, γ = geometric margin of best hyperplane

The fatal flaw: The step function is not differentiable at 0, so gradient descent cannot be applied. The Perceptron cannot learn non-linear boundaries at all — the XOR problem, proved by Minsky & Papert in 1969, triggered the first AI winter.

The Modern Forward Pass

A neural network is a sequence of matrix multiplications passed through non-linear gates. For layer ℓ:

Forward Pass Equations Z[ℓ] = W[ℓ] · A[ℓ⁻¹] + b[ℓ] A[ℓ] = g[ℓ](Z[ℓ]) W[ℓ] = weight matrix, b[ℓ] = bias vector, g[ℓ] = activation function, A[0] = X (input)
🎯 Symmetry Breaking — The #1 Initialization Trap

Q: Can I initialize all weights to 0?

A: "Absolutely not. If all weights are zero, every neuron in a hidden layer computes Z = 0·X + b — identical for every neuron. During backpropagation, they all receive the exact same gradient ∂L/∂W and update identically. The network permanently learns only one feature, no matter how many neurons you add. This is the Symmetry Problem. We must break symmetry with random initialization (Xavier or He) so each neuron can specialize in different features."

🎯 Dimensionality Trap

Q: Layer 1 has 128 neurons, Layer 2 has 64. What is the shape of W?

A: "If input X has shape (128, m) where m is batch size, then W[2] must have shape (64, 128) to produce Z[2] = W[2]·X of shape (64, m). The bias b[2] has shape (64, 1) and broadcasts. In PyTorch, nn.Linear(128, 64) creates W of shape (64, 128) — input features are columns, output features are rows. This confusion causes the majority of shape mismatch bugs in production PyTorch code."

🎯 Bias Geometric Meaning

Q: What happens if you remove the bias term from all layers?

A: "Without bias, every decision hyperplane is forced to pass through the origin (0,0,…,0). The network loses a critical degree of freedom — it cannot shift its activation function left or right, only scale it. If the positive class data is clustered far from the origin, the model will struggle to find a clean separating boundary. Geometrically, bias translates the hyperplane; without it, we're restricted to hyperplanes through the origin — a massive constraint that can prevent learning even simple patterns."

Universal Approximation Theorem

The Theory: A feedforward network with at least one hidden layer using a non-polynomial activation function, and a linear output layer, can approximate any continuous function f: ℝⁿ → ℝᵐ to any desired accuracy ε > 0, provided the hidden layer has enough neurons.

The "Wide vs Deep" Question: The theorem guarantees width (one infinite hidden layer) is sufficient. But in practice, we use depth. Why?

  • Deep networks compose features hierarchically: Layer 1 learns edges → Layer 2 learns textures → Layer 3 learns parts → Layer 4 learns objects
  • A deep network can represent the same function as a wide network with exponentially fewer parameters
  • Mathematically: the class of functions representable by a depth-k network requires exponentially more neurons in a depth-1 network to approximate (Telgarsky, 2016)

VRAM Engineering Calculations

🎯 Memory Math — Applied Engineering Round

Q: How much GPU memory does training a 7B parameter model require?

A: "In FP32, each parameter takes 4 bytes. 7B × 4B = 28GB just for weights. During training with Adam: weights (28GB) + gradients (28GB) + Adam's two optimizer states per parameter — first and second moment (56GB) = ~112GB total. That's why we use BF16 mixed precision: weights in BF16 (~14GB) + master weights in FP32 for optimizer stability (~28GB) + gradients (~14GB) + optimizer states (~28GB) = ~84GB. Still requires multiple A100s (80GB each). This is why FSDP/ZeRO sharding exists."

# Memory estimation utility
def estimate_training_memory(n_params, dtype='fp32'):
    bytes_per_param = {'fp32': 4, 'fp16': 2, 'bf16': 2}[dtype]
    weights     = n_params * bytes_per_param
    gradients   = n_params * bytes_per_param
    adam_states = n_params * 4 * 2  # fp32 for stability: m_t and v_t
    total_gb    = (weights + gradients + adam_states) / 1e9
    print(f"Weights:        {weights/1e9:.1f} GB")
    print(f"Gradients:      {gradients/1e9:.1f} GB")
    print(f"Optimizer:      {adam_states/1e9:.1f} GB")
    print(f"Total:          {total_gb:.1f} GB")

estimate_training_memory(7e9, dtype='bf16')

Activation Functions — Complete Mathematical Treatment

Activation functions inject non-linearity. Without them, stacking N linear layers collapses mathematically to Z_N = (W_N · W_{N-1} ··· W_1)X — a single equivalent linear transformation, identical to basic Linear Regression regardless of depth. Activations are what let networks learn curves, spirals, and complex decision surfaces.

The Vanishing Gradient — Mathematical Proof

Why Sigmoid Killed Deep Networks (1990s AI Winter)

The derivative of Sigmoid is σ′(z) = σ(z)(1−σ(z)). The maximum value occurs at z=0: σ(0)·(1−σ(0)) = 0.5 × 0.5 = 0.25. This is an absolute ceiling — it can never exceed 0.25.

In backpropagation, we multiply gradients across all layers via the chain rule:

∂L/∂W[1] = ∂L/∂A[n] · ∏ₖ σ′(Z[k]) · W[k]

For a 10-layer network with all Sigmoid activations, the gradient product contains at minimum 0.25¹⁰ = 9.5 × 10⁻⁷. The gradient at Layer 1 is effectively zero — the layer stops learning entirely. This is the mathematical cause of the 1990s AI winter. ReLU fixed this: its derivative is exactly 1 for positive inputs, so multiplying 1×1×1×... never vanishes.

GELU — The Transformer Standard

GELU (Gaussian Error Linear Unit) is defined as f(z) = z·Φ(z) where Φ(z) is the Gaussian CDF: Φ(z) = ½·[1 + erf(z/√2)].

Intuition: GELU stochastically decides whether to pass a neuron's input, with the probability determined by how large the input is relative to a standard normal distribution. Large positive values almost always pass through; large negative values almost always get zeroed. Near zero, it's a smooth probabilistic gate — this smooth stochasticity gives Transformers extra expressiveness.

Fast approximation used in practice (Hendrycks, 2016):

GELU(x) ≈ 0.5x · (1 + tanh(√(2/π) · (x + 0.044715x³))) BERT, GPT-2/3/4, T5, LLaMA all use GELU or this approximation
⚠️ Dying ReLU Problem

If a large gradient update pushes a neuron's weights such that W·X + b < 0 for ALL training examples, the ReLU outputs 0 and its gradient is permanently 0. The neuron is "dead" — it will never receive another gradient update regardless of future inputs. In practice, ~10–20% of neurons can die in poorly initialised deep networks. Fix: Leaky ReLU, ELU, or proper He initialisation + gradient clipping.

# Check for dead neurons in a trained model
def count_dead_neurons(model, X_sample):
    dead = 0; total = 0; hooks = []
    def hook(m, inp, out):
        nonlocal dead, total
        if isinstance(m, nn.ReLU):
            dead  += (out == 0).float().mean().item() * out.numel()
            total += out.numel()
    for m in model.modules(): hooks.append(m.register_forward_hook(hook))
    with torch.no_grad(): model(X_sample)
    for h in hooks: h.remove()
    return dead / total * 100  # % dead neuronspython

Backpropagation — The Chain Rule Engine

Forward pass makes a prediction. The Loss measures the mistake. Backpropagation answers: how much did each weight contribute to that mistake? It is the Chain Rule of Calculus applied systematically to a computational graph — nothing more, nothing less.

The Core Chain Rule

Backprop Chain — From Loss to First Layer Weight ∂L/∂W[1] = (∂L/∂ŷ) · (∂ŷ/∂A[n]) · (∂A[n]/∂Z[n]) · (∂Z[n]/∂A[n-1]) ··· (∂Z[1]/∂W[1])

Step-by-Step for a 2-Layer Network

  1. 1
    Compute loss gradient: δᵒᵘᵗ = ∂L/∂Z[2] = ŷ − y (for Softmax + Cross-Entropy — the chain rule telescopes beautifully into just the prediction error)
  2. 2
    Gradient w.r.t. W²: ∂L/∂W[2] = δᵒᵘᵗ · (A[1])ᵀ — note A[1] must be stored from the forward pass. This is the fundamental reason activations consume memory.
  3. 3
    Propagate backward: δ[1] = (W[2])ᵀ · δᵒᵘᵗ ⊙ g′[1](Z[1]) where ⊙ is elementwise multiply and g′ is the activation's derivative
  4. 4
    Gradient w.r.t. W¹: ∂L/∂W[1] = δ[1] · Xᵀ
  5. 5
    Update all weights simultaneously: W[ℓ] ← W[ℓ] − α · ∂L/∂W[ℓ]

Autograd & Computational Graphs (PyTorch Internals)

PyTorch builds a Directed Acyclic Graph (DAG) dynamically during the forward pass. Every tensor operation creates a node. When you call .backward(), the engine traverses this graph in reverse topological order (reverse-mode automatic differentiation).

  • Leaf tensors: Your model weights — they require gradients (requires_grad=True)
  • Non-leaf tensors: Intermediate activations — created during computation, freed after .backward() unless retain_graph=True
  • GradFn: Every non-leaf tensor stores a reference to the operation that created it (e.g., MmBackward0 for matrix multiply) so the backward pass knows which function to differentiate

Forward vs Reverse Mode Automatic Differentiation

The Jacobian Argument — Why Reverse Mode is Non-Negotiable for Training

A neural network is f: ℝᴺ → ℝᴹ where N = 10⁸ parameters and M = 1 (the scalar loss). The full derivative is a Jacobian matrix J ∈ ℝᴹˣᴺ. We need every entry.

Forward Mode (JVP): Push a unit vector eᵢ (representing parameter i) through the graph once → get column i of J. Repeat for all N parameters → O(N) passes = 10⁸ passes.

Reverse Mode (VJP = Backprop): Pull the output gradient 1ᵀ (a single 1×M row vector since M=1) backward through the graph once → get all N entries of J simultaneously → O(M) = 1 pass.

Since M=1 ≪ N=10⁸, reverse mode is 10⁸× faster. This is why backpropagation makes deep learning physically possible. Forward mode is only preferred when N ≪ M (rare: sensitivity analysis of small models).

Activation Memory & Gradient Checkpointing

The Mathematical Reason Activations Must Be Stored: To compute ∂L/∂W[2] = δᵒᵘᵗ · (A[1])ᵀ, we need A[1] — the output of layer 1 from the forward pass. PyTorch cannot delete it until backprop is complete. For a 100-layer network with batch size 64 and feature dimension 1024:

Activation Memory = 100 layers × 64 × 1024 × 4 bytes ≈ 26 GB This dwarfs the weights themselves and is the primary cause of CUDA Out of Memory during training
🔑 Gradient Checkpointing — Trading Compute for Memory

Technique: Instead of storing all N intermediate activations, store only every √N-th layer's activations (checkpoints). During backprop, recompute the activations between checkpoints on-the-fly.

Trade-off: Memory usage drops from O(N) to O(√N), but training takes ~33% longer due to the recomputation.

Why inference is memory-cheap: With torch.no_grad(), PyTorch knows no backward pass is needed — activations are immediately discarded after each layer. Only one layer's activations exist in VRAM at any time, making memory usage constant regardless of network depth.

import torch
from torch.utils.checkpoint import checkpoint

# Gradient checkpointing — trades compute for memory (~33% slower, O(√N) memory)
class CheckpointedBlock(nn.Module):
    def forward(self, x):
        return checkpoint(self._forward, x, use_reentrant=False)
    def _forward(self, x): return self.layers(x)

# Inference — no gradients stored, constant memory regardless of depth
model.eval()
with torch.no_grad():
    predictions = model(x_test)   # activations freed immediately

# Visualise computational graph (small example)
x = torch.randn(3, requires_grad=True)

🎯 Why Not MSE for Classification?

A: "Using MSE with Sigmoid/Softmax output creates a highly non-convex loss landscape riddled with flat plateaus where gradients are near-zero. Additionally, MSE doesn't penalise confident wrong predictions harshly enough — a probability of 0.99 predicting the wrong class has an MSE of (1−0.99)² = 0.0001, negligible. Cross-Entropy loss grows logarithmically (approaching infinity for confident wrong predictions). Mathematically, Softmax + Cross-Entropy gives an elegant gradient: ∂L/∂Z = ŷ − y — no messy chain rule through the exponentials, just the prediction error."

SGD with Momentum

Momentum Update Rule v_t = β·v_{t-1} + (1−β)·∇L(θ_t) θ_t = θ_{t-1} − α·v_t β = 0.9 typical. v accumulates gradients like a ball rolling downhill.

The velocity v accumulates gradients like a ball rolling downhill — it builds momentum in consistent directions (along the ravine bottom) and dampens oscillations in inconsistent directions.

Adam — Adaptive Moment Estimation

Adam Full Algorithm m_t = β₁·m_{t-1} + (1−β₁)·g_t ← 1st moment: mean gradient (direction) v_t = β₂·v_{t-1} + (1−β₂)·g_t² ← 2nd moment: uncentred variance (scale) m̂_t = m_t / (1−β₁ᵗ) v̂_t = v_t / (1−β₂ᵗ) ← bias correction θ ← θ − α · m̂_t / (√v̂_t + ε) Defaults: β₁=0.9, β₂=0.999, ε=1e-8, α=3e-4
⭐ Adam's Secret Weapon: Bias Correction

Both m_t and v_t are initialised to 0. At step 1: m₁ = (1−β₁)·g₁ ≈ 0.1·g₁ — artificially biased toward zero. Without correction, the first few updates are tiny regardless of gradient magnitude. The bias correction m̂_t = m_t / (1−β₁ᵗ) divides by 0.1 at step 1, correctly scaling up the update. As t → ∞, (1−β₁ᵗ) → 1 and the correction vanishes automatically. This is why Adam trains stably from step 1 while vanilla momentum can take dozens of steps to "warm up."

Weight Initialisation — The Variance Derivation

Mathematical Proof of Xavier Initialisation

Consider one neuron: y = Σᵢ wᵢxᵢ where weights wᵢ and inputs xᵢ are independent with mean 0.

Variance of a product of independent zero-mean variables: Var(wᵢxᵢ) = Var(wᵢ) · Var(xᵢ)

For n independent terms: Var(y) = n · Var(wᵢ) · Var(xᵢ)

Goal: We want Var(y) = Var(xᵢ) so signal flows without shrinking or exploding. Setting n·Var(wᵢ) = 1 → Var(wᵢ) = 1/n. This is Xavier (Glorot) initialisation.

He Initialisation for ReLU: ReLU kills all negative activations, cutting the effective variance by half. To compensate: Var(wᵢ) = 2/n. Double it to account for the 50% zeroing.

Chapter 66

Regularisation & Stability — Production Engineering

Dropout — Engineering and Bayesian Science

During training, randomly zero out each neuron's output with probability p. The intuition: prevent any single neuron from becoming a "dominant employee" the network always relies on. Forces redundant representations.

Inverted Dropout (How All Frameworks Actually Implement It)

Inverted Dropout — Training A[ℓ] = A[ℓ] · Bernoulli(1−p) / (1−p) Dividing by (1−p) during training scales surviving activations up. At inference: nothing changes — no multiplication needed.

This is the engineering win: inference runs at maximum hardware speed with zero modification. The expected value of the layer output is preserved during training, so the network's behaviour doesn't shift at inference time.

🔬 MC Dropout — Bayesian Uncertainty (Research Level)

Q: Neural nets are overconfident. How do you get uncertainty estimates without retraining?

A: Monte Carlo Dropout (Gal & Ghahramani, 2016). A neural network trained with Dropout is mathematically equivalent to approximate variational inference in a deep Gaussian process. To exploit this: keep Dropout active during inference. Run the same input T=100 times — each produces a different prediction (different neurons dropped). The mean is your prediction. The variance is your uncertainty estimate. High variance = "I don't know."

model.train()  # keep dropout active at inference!
with torch.no_grad():
    preds = torch.stack([model(x) for _ in range(100)])
mean        = preds.mean(0)   # prediction
uncertainty = preds.var(0)    # epistemic uncertaintypython

Batch Normalisation — The Real Mechanism

Batch Norm Forward Pass μ_B = (1/m)·Σxᵢ σ²_B = (1/m)·Σ(xᵢ−μ_B)² x̂ᵢ = (xᵢ−μ_B) / √(σ²_B+ε) yᵢ = γ·x̂ᵢ + β γ and β are learnable per-channel scale and shift parameters — allow network to undo normalisation if needed
⚠️ The Inference Trap — #1 PyTorch Production Bug

BatchNorm computes μ and σ² across the batch. At inference with batch size = 1: variance of a single sample is 0 → division by near-zero → unstable outputs.

Fix: During training, BatchNorm maintains an Exponential Moving Average (EMA) of batch statistics: μ_EMA ← α·μ_EMA + (1−α)·μ_B. When you call model.eval(), PyTorch uses these stored EMA statistics instead of computing from the current batch. Batch dimension becomes irrelevant.

Bug pattern: Forgetting to call model.eval() before inference → BatchNorm uses single-sample statistics → completely wrong outputs compared to training.

🔬 Why BatchNorm Actually Works (The 2018 Rebuttal)

The original 2015 paper (Ioffe & Szegedy) claimed BatchNorm works by fixing "Internal Covariate Shift" (ICS) — the changing distribution of layer inputs as earlier layers update. MIT researchers (Santurkar et al., 2018) disproved this by adding explicit ICS after BatchNorm layers — the network still trained perfectly. Their finding: BatchNorm smoothens the optimisation landscape. It bounds the Lipschitz constant of the loss, limiting how fast the gradient can change as you move in parameter space. A smoother landscape → larger learning rates are safe → faster convergence. The true mechanism is geometric, not distributional.

AdamW — Decoupled Weight Decay (The LLM Enabler)

Why L2 Regularisation ≠ Weight Decay in Adam

In SGD: Adding λ/2·||W||² to the loss gives gradient g_t + λW. Update: W ← W − α(g_t + λW) = W(1−αλ) − αg_t. L2 regularisation and weight decay are the same equation — identical.

In Adam: The full L2 gradient (g_t + λW) gets normalised by √v̂_t. The weight decay term λW is divided by different amounts for different parameters. Parameters with large historical gradients (large v̂_t) get their weight decay heavily throttled. The regularisation is uneven and broken — the most active weights (most likely to overfit) get the least penalty.

AdamW fix: Compute the adaptive gradient step first, then apply weight decay directly to weights:

W ← W − α·(m̂_t / (√v̂_t + ε) + λ·W)

The λW term is outside the adaptive normalisation — every parameter gets uniform regularisation regardless of gradient history. This is why AdamW is the standard for training LLMs.

Gradient Clipping — Preventing NaN Explosions

L2 Norm Gradient Clipping g_new = g · min(1, threshold / ||g||₂) Preserves direction — only scales magnitude. Clipping individual values changes direction (wrong!).

Label Smoothing

One-hot targets [1,0,0] push Softmax output toward exactly 1.0. The only way to achieve softmax(z₁) = 1.0 is z₁ → +∞, which requires weights to grow without bound → catastrophic overfitting. Label smoothing prevents this:

y_k^LS = (1−ε)·y_k + ε/K With ε=0.1 and K=3 classes: [1,0,0] → [0.933, 0.033, 0.033]. Model satisfied without infinite weights. 
import torch.nn as nn

# All normalisation types
bn  = nn.BatchNorm2d(256)         # CNNs with large batches
ln  = nn.LayerNorm(768)            # Transformers — feature dim

Convolutional Neural Networks — Full Mathematical Treatment

Dense layers fail on images. A 1000×1000 image with a single 1000-neuron dense hidden layer requires 10⁶ × 10³ = 10⁹ parameters. CNNs exploit spatial structure through two inductive biases: locality (nearby pixels are related) and translation equivariance (a cat ear top-left and bottom-right are the same feature).

The Convolution Operation

2D Cross-Correlation (What PyTorch Actually Computes) (X ★ W)[i,j] = Σₖ Σₗ X[i+k, j+l] · W[k,l] Filter W (kernel) of size K×K slides across input X. PyTorch uses cross-correlation (no kernel flip) — since kernels are learned, it makes no practical difference.

Output Dimension Formula — Memorise This

H_out = ⌊(H_in − K + 2P) / S⌋ + 1 K = kernel size, P = padding, S = stride. Same formula for W_out.

FLOPs Cost of a Conv Layer

FLOPs ≈ 2 × C_in × C_out × K² × H_out × W_out Doubling image resolution increases FLOPs by 4×. This is why EfficientNet scales resolution carefully.

ResNet — Solving Deep Network Degradation (2015)

The Problem: Before ResNet, adding more layers made training accuracy worse, not just test accuracy. The 56-layer network had higher training error than the 20-layer network. This wasn't overfitting — it was shattered gradients. Multiplying 50+ Jacobian matrices creates matrices with tiny eigenvalues — gradients vanish before reaching early layers.

Residual Block: H(x) = F(x) + x H(x) = F(x, {Wᵢ}) + x Instead of learning H(x) directly, layers learn the residual F(x) = H(x) − x. If optimal is close to identity, F(x) ≈ 0 — much easier to learn than the full mapping.

Backprop through the skip connection:

∂L/∂x = ∂L/∂H · (∂F/∂x + 1) The +1 term creates a "gradient superhighway" — signal flows backward without attenuation regardless of ∂F/∂x. This same principle powers Transformers (every block has x + Sublayer(x)).

EfficientNet — Compound Scaling (2019)

If you have more compute budget, should you make the network deeper, wider, or use higher resolution? All three together, uniformly. These dimensions are coupled — increasing resolution without depth means the network can't capture the full image.

Compound Scaling Coefficients depth: d = αᶠ width: w = βᶠ resolution: r = γᶠ Subject to: α · β² · γ² ≈ 2, φ controls total compute. EfficientNet-B0→B7: φ = 0,1,…,7

YOLO — You Only Look Once

YOLO frames detection as a single regression problem on a grid. Divide the image into S×S grid cells (e.g., 7×7). Each cell predicts B bounding boxes:

Output ∈ ℝ^(S × S × (B×5 + C)) Each box: (x, y, w, h, confidence) + C class probabilities. Confidence = P(object) × IoU(pred, truth)

Non-Maximum Suppression (NMS): Multiple cells detect the same object → overlapping boxes. Sort by confidence, keep highest, delete boxes with IoU > threshold (they're duplicates), repeat.

IoU(A,B) = |A∩B| / |A∪B| = Intersection Area / (Area(A) + Area(B) − Intersection Area)
🎯 Focal Loss — Why YOLO Needs It

Q: Most of a detection image's grid cells are background. How does YOLO avoid the model just predicting "background" everywhere?

A: "Focal Loss (Lin et al., 2017): FL(p) = −(1−p_t)ᵞ · log(p_t). When the model correctly predicts background with high confidence (easy negative), (1−p_t)ᵞ is near 0 — loss contribution down-weighted. Hard examples have (1−p_t)ᵞ ≈ 1 — full gradient signal. With γ=2, easy examples contribute 1000× less to total loss than hard ones. The detector learns to focus entirely on the rare, difficult object detections."

RNNs, LSTMs & GRUs — Sequential Memory

Vanilla RNN

RNN Hidden State Update h_t = tanh(W_hh · h_{t-1} + W_xh · x_t + b_h) ŷ_t = W_hy · h_t + b_y h_t = compressed memory of everything seen up to time t

BPTT and the Vanishing/Exploding Gradient

Mathematical Proof of Vanishing Gradients in RNNs

The gradient of loss at time t w.r.t. hidden state at time k < t:

∂L_t/∂h_k = ∂L_t/∂h_t · ∏ⱼ W_hh^T · diag(tanh′(Z_j))

The dominant term is W_hh^(t−k) — the weight matrix raised to the power of the sequence length gap. If largest eigenvalue λ_max(W_hh) < 1: λ_max^(t−k) → 0 exponentially → vanishing gradients. If λ_max > 1: → ∞ → exploding gradients. Only λ_max = 1 is stable — an infinitely precise condition impossible to maintain during training.

LSTM — Long Short-Term Memory

LSTMs introduce a Cell State C_t — a highway with only additive interactions. Additive interactions have gradient = 1 — they don't vanish. The key insight: replace multiplicative recurrence with additive recurrence in the cell state path.

LSTM Equations — All Four Gates f_t = σ(W_f · [h_{t-1}, x_t] + b_f) ← Forget Gate i_t = σ(W_i · [h_{t-1}, x_t] + b_i) ← Input Gate C̃_t = tanh(W_C · [h_{t-1}, x_t] + b_C) ← Cell Candidate C_t = f_t ⊙ C_{t-1} + i_t ⊙ C̃_t ← Cell State Update (additive!) o_t = σ(W_o · [h_{t-1}, x_t] + b_o) ← Output Gate h_t = o_t ⊙ tanh(C_t) ← Hidden State
🎯 Why Sigmoid for Gates, Tanh for Data?

A: "Sigmoid acts as a physical valve — values in (0,1). Multiplying by σ keeps a percentage of information (1.0=keep all, 0.0=delete all). This is exactly the semantics of forgetting and remembering. Tanh is used for the cell candidate and output because: (1) it's zero-centred, allowing the network to both add and subtract from memory, (2) it bounds values to (−1,1), preventing the cell state from growing unboundedly over long sequences — which would cause numerical overflow."

🎯 How do LSTMs Actually Solve Vanishing Gradients?

A: "Look at the cell state update: C_t = f_t ⊙ C_{t-1} + i_t ⊙ C̃_t. The gradient of C_t w.r.t. C_{t-1} is f_t (the forget gate value). Unlike the vanilla RNN where we always multiply by W_hh (potentially collapsing), here we multiply by f_t ∈ (0,1) — a learned, soft value that can stay close to 1 for as long as the network needs to remember something. Crucially, the cell state path has only additive connections — gradient flows through the '+' sign without attenuation. This is the key difference: RNN has multiplicative recurrence; LSTM has additive recurrence in the cell state."

GRU — Gated Recurrent Unit (2014)

GRU achieves similar performance to LSTM with fewer parameters by merging cell state and hidden state, using only 2 gates:

z_t = σ(W_z·[h_{t-1}, x_t]) ← Update Gate r_t = σ(W_r·[h_{t-1}, x_t]) ← Reset Gate h̃_t = tanh(W·[r_t ⊙ h_{t-1}, x_t]) ← Candidate State h_t = (1−z_t) ⊙ h_{t-1} + z_t ⊙ h̃_t

The Optimisation Landscape — Deep Dive

Nesterov Accelerated Gradient (NAG) — The Lookahead Correction

Standard Momentum is blind. It accumulates massive speed rolling down a hill, but if the hill suddenly curves upward, it doesn't realise it until it has already overshot.

Nesterov says: If our momentum is going to push parameters by ≈μv_{t-1}, why not calculate the gradient at that future projected position, rather than the current one?

Nesterov Accelerated Gradient (NAG) θ̃ = θ_{t-1} + μ·v_{t-1} ← project to future position g_t = ∇L(θ̃) ← gradient at FUTURE position v_t = μ·v_{t-1} − α·g_t θ_t = θ_{t-1} + v_t By computing gradient at the projected position, NAG acts as an emergency brake — it corrects course before overshooting.

AdaGrad — The First Adaptive Optimizer

One global learning rate for 10⁸ parameters is terrible for sparse features (NLP, where "the" updates millions of times but "xylophone" updates once). AdaGrad introduced per-parameter learning rates:

G_t = G_{t-1} + g_t² ← sum of ALL past squared gradients θ_t = θ_{t-1} − (α / √(G_t + ε)) · g_t

Fatal Flaw: G_t is strictly positive and monotonically increasing. Over time, α/√G_t → 0 and the network completely stops learning. AdaGrad "burns out."

RMSprop — Fixing AdaGrad's Memory

Instead of summing all past squared gradients, use an exponentially weighted moving average — the optimizer "forgets" the distant past:

E[g²]_t = β·E[g²]_{t-1} + (1−β)·g_t² ← decaying average, not sum θ_t = θ_{t-1} − (α / √(E[g²]_t + ε)) · g_t β ≈ 0.99. If a param had huge gradients 10,000 steps ago but is flat now, denominator shrinks → learning rate recovers.

Advanced Optimizers: AdaMax, AMSGrad, Lion

AdaMax: Instead of the L2 norm (√v_t), uses the L∞ norm — take the max of absolute gradients instead of their RMS. Provably more stable for certain sparse gradient problems.

u_t = max(β₂·u_{t-1}, |g_t|) ← L∞ second moment θ ← θ − (α / u_t) · m̂_t

AMSGrad: Standard Adam doesn't guarantee convergence — v_t can decrease, allowing learning rate to spike upward unexpectedly. AMSGrad fixes this by using a running max of v̂_t:

v̂_t_max = max(v̂_{t-1}_max, v̂_t) ← always non-decreasing θ ← θ − α · m̂_t / (√v̂_t_max + ε)

Lion (EvoLved Sign Momentum, Google Brain 2023): Discovered by AI searching for algorithms. Drops the second moment entirely — cuts optimizer memory in half for massive LLMs:

c_t = β₁·m_{t-1} + (1−β₁)·g_t ← momentum θ ← θ − α · sign(c_t) ← update is just the sign! m_t = β₂·m_{t-1} + (1−β₂)·g_t ← update momentum Only one moving average stored vs. two for Adam. Halves optimizer memory for 70B+ models.

Momentum Cancellation — The Full Mathematical Proof

Unrolling the momentum recurrence (assuming v₀=0):

v_t = −α · Σᵢ₌₁ᵗ μ^(t-i) · gᵢ Velocity is an exponentially decaying weighted sum of all past gradients.
Proof 1: How Consistent Gradients Build Speed

If gradients are roughly constant (straight slope): gᵢ ≈ c for all i.

v_t = −αc · Σᵢ₌₁ᵗ μ^(t-i) = −αc · (1 + μ + μ² + ···) → −αc · 1/(1−μ)

With μ=0.9: terminal velocity = −αc · 1/(1−0.9) = −10αc

Momentum accelerates to 10× the speed of standard SGD in a consistent gradient direction. This is the mathematical proof of the speed build-up.

Proof 2: How Oscillating Gradients Cancel

If gradients alternate sign (ravine walls): gᵢ = (−1)ⁱ·c

v_t ∝ −αc · (1 − μ + μ² − μ³ + ···) = −αc · 1/(1+μ)

With μ=0.9: terminal velocity = −αc · 1/(1+0.9) ≈ 0.52·αc

The effective step size in the oscillating direction is nearly halved. Opposing gradients destructively interfere.

Combined result: Momentum moves 10× faster in the consistent direction and 0.52× slower in the oscillating direction — a ratio of 19:1. This is why momentum solves the ravine problem.

Why AdamW Matters Specifically for LLMs

🎯 The LLM-Specific Problem — Full Explanation

Q: Why does the Adam vs AdamW distinction matter specifically for LLMs/NLP and not for simple CNNs?

A:

1. NLP is Sparse and Spiky: In CV, every pixel updates consistently. In NLP, the word "the" appears in every sentence → updates millions of times. "Defenestrate" appears once → updates once. Furthermore, Transformer attention creates massive gradient spikes when the model discovers two distant tokens are related. This sparsity means you MUST use an adaptive optimizer like Adam — SGD fails completely.

2. The Bug in Standard Adam + Weight Decay: To prevent LLM overfitting (billions of parameters), we need weight decay. Adding L2 penalty gives gradient: g_t + λθ_t. In SGD, this works perfectly. In Adam, the full gradient gets divided by √v̂_t. For a highly active attention weight with massive historical gradients, v̂_t is huge → λθ_t / √v̂_t becomes tiny → the regularisation penalty is almost zero → the most active weights get the LEAST penalty → those are exactly the weights most likely to overfit.

3. AdamW fix: Apply weight decay after the Adam step, outside the adaptive normalisation: θ ← θ − α·(m̂_t/(√v̂_t+ε)) − αλθ. Every parameter experiences identical decay regardless of gradient history. This single fix is what enabled GPT-3, LLaMA, and every modern LLM to train without memorising training data.

Hyperparameter Tuning — Grid vs Random vs Bayesian

CV = Cross-Validation. We use k-fold cross-validation to evaluate each hyperparameter configuration: split training data into k folds, train on k−1, evaluate on the held-out fold, rotate k times, average the scores. This avoids using the test set for model selection — which would cause data leakage.

GridSearchCV

You provide a strict grid of values: e.g., LR ∈ {0.1, 0.01, 0.001}, Batch ∈ {32, 64}. The algorithm exhaustively tries every single combination (3 × 2 = 6 configurations). Scales exponentially: 5 parameters × 5 values = 3,125 trials.

RandomizedSearchCV

You provide statistical distributions (e.g., LR ~ Uniform(0.001, 0.1)). The algorithm randomly samples a fixed number of configurations.

🔑 CS231n Defence: Why Random > Grid

In most neural networks, only a few hyperparameters critically determine success. If you use a 3×3 grid search across two parameters, you only test 3 distinct values of each parameter. If you use 9 iterations of random search, you test 9 completely distinct values of the important parameter — dramatically higher chance of finding the true optimum. As the dimensionality grows, random search's advantage compounds exponentially. Grid search wastes evaluations on parameter combinations where one parameter doesn't matter.

Bayesian Optimisation

Builds a probabilistic surrogate model (Gaussian Process) of the objective function from previous evaluations. Uses an acquisition function (e.g., Expected Improvement) to decide which hyperparameter configuration to try next — actively learns which regions of the search space are promising. Requires ~10× fewer evaluations than random search for smooth objectives. Libraries: Optuna, Hyperopt, Ax (Facebook).

CS231n Engineering Sanity Checks — Before You Train

These are mandatory verification steps from Stanford's CS231n. Skip them and you'll waste days debugging a silently broken model.

1. Gradient Checking

Backpropagation is notoriously bug-prone (transposed matrix, missing factor of 2, wrong sign). Verify analytical gradients against numerical gradients via the finite difference formula:

df/dx ≈ (f(x+h) − f(x−h)) / (2h) with h ≈ 1e-5 Relative error = |analytical − numerical| / (|analytical| + |numerical|) should be < 1e-4. If > 1e-2, your backprop has a bug. 
def gradient_check(loss_fn, params, eps=1e-5):
    analytical = loss_fn(params).backward()  # computed via autograd
    numerical_grads = []
    for i in range(len(params)):
        params[i] += eps; L_plus  = loss_fn(params)
        params[i] -= 2*eps; L_minus = loss_fn(params)
        params[i] += eps  # restore
        numerical_grads.append((L_plus - L_minus) / (2*eps))
    relative_error = abs(analytical - numerical_grads) / (abs(analytical) + abs(numerical_grads))
    assert relative_error < 1e-4, f"Gradient check failed: {relative_error}"python

2. Look for Chance Performance at Initialisation

If you initialise a model to classify 10 classes (like CIFAR-10), the initial loss before any training must exactly equal −log(1/10) = −log(0.1) = 2.302. If it doesn't, your initialisation or softmax logic is completely broken.

Initial Loss (K classes) = −log(1/K) = log(K) CIFAR-10 (K=10): expect 2.302. ImageNet (K=1000): expect 6.908. Binary (K=2): expect 0.693

3. Overfit a Tiny Subset — The Golden Test

Take exactly 5–20 examples from your dataset and turn off ALL regularisation (dropout=0, weight_decay=0, no augmentation). Train the network. It must achieve exactly 0.0 loss and 100% training accuracy.

If the loss plateaus above 0, your architectural wiring is fundamentally flawed — likely a shape mismatch, a disconnected gradient, or a bug in the loss function. This test is far faster than diagnosing a full training run.

4. Monitor the Loss During Training

  • Loss not decreasing: Learning rate too small, or gradients vanishing (check activation choice, initialisation)
  • Loss exploding to NaN: Learning rate too large, or gradients exploding (add gradient clipping)
  • Loss decreases then plateaus: Learning rate needs scheduling; or model capacity too small
  • Train loss << Val loss: Overfitting — add regularisation, dropout, data augmentation, reduce model size
  • Both train and val loss high: Underfitting — increase model capacity, train longer, check preprocessing

model.eval()
with torch.no_grad():
    logits = model(X_train[:32])  # small batch
    loss   = nn.CrossEntropyLoss()(logits, y_train[:32])
assert abs(loss.item() - torch.log(torch.tensor(float(num_classes))).item()) < 0.1, \

CDC Interview Bank

Rapid-Fire Interview Reference — Deep Learning

Explain the vanishing gradient problem and all known solutions.
Three-level answer. (1) Architecture solutions: ReLU activation (gradient = 1 for positive inputs, no shrinkage); skip connections in ResNets (+1 gradient superhighway); LSTM cell state (additive recurrence). (2) Initialisation solutions: He init for ReLU networks prevents gradient explosion/vanishing at the start of training. (3) Normalisation solutions: BatchNorm/LayerNorm regularise gradient magnitude by bounding the Lipschitz constant of the loss landscape. Gradient clipping handles the exploding side. All three are used together in modern LLMs.
Why is PyTorch's autograd called "dynamic computation graphs" and how does it differ from TensorFlow 1.x?
TF1 used static graphs: define the entire computation graph symbolically, then execute via tf.Session. Graph compiled once — heavily optimised, but can't change at runtime; debugging is painful; control flow requires special ops (tf.cond, tf.while_loop). PyTorch builds the graph dynamically — each forward pass creates a fresh DAG based on actual executed operations. Real Python control flow (if/for), easy debugging (inspect any tensor), variable-length inputs. Trade-off: less ahead-of-time graph optimisation, though PyTorch 2.0's torch.compile() largely closes this gap by JIT-compiling the dynamic graph.
What is transfer learning, and when does fine-tuning full weights vs. only the head make sense?
Transfer learning exploits the fact that early CNN layers learn universal features (edge detectors, color gradients, Gabor filters) present in all natural images. Strategy depends on two factors — dataset size and domain similarity: (1) Large data + similar domain: fine-tune all layers with a small LR to adapt without destroying pretrained features. (2) Small data + similar domain: freeze backbone, train only new head. Prevent overfitting on small data. (3) Large data + different domain: fine-tune all layers, possibly with higher LR on later layers (differential LRs). (4) Small data + different domain: most difficult case. Fine-tune only last few layers; be cautious of overfitting. In practice, use differential learning rates — 10–100× smaller LR for frozen/pretrained layers vs. the new head.
What is the difference between model.train() and model.eval() in PyTorch?
Two layers behave fundamentally differently. (1) Dropout: train mode → neurons dropped with probability p, surviving activations scaled by 1/(1−p). eval mode → all neurons active, no scaling. (2) BatchNorm: train mode → computes statistics from current mini-batch AND updates the running EMA. eval mode → uses stored running mean/variance, ignores the batch entirely. Forgetting model.eval() before inference is a common production bug: BatchNorm behaves unpredictably at batch size 1, and Dropout introduces random noise into deterministic predictions. The fix is one line of code but takes hours to diagnose.
A model trains well but performs much worse at inference time. How do you diagnose this?
Structured debugging checklist: (1) model.eval() forgotten — Dropout active, BatchNorm using batch stats → massive prediction noise. (2) Preprocessing mismatch — training and inference used different normalisation statistics. (3) Data leakage — validation used training statistics (must fit scaler on train only, transform both). (4) Distribution shift — inference data has different distribution (different camera, user demographics). Compare train vs inference data statistics. (5) Stochastic ops left on — random seeds, augmentation left active at inference. (6) Mixed precision overflow — FP16 NaN in edge cases not seen during training.
Why does increasing batch size not linearly scale GPU performance?
Three bottlenecks. (1) Memory bandwidth: At small batches, GPU is compute-bound (cores busy). At large batches, we hit memory bandwidth limits — data can't move to/from VRAM fast enough. (2) Generalisation degradation: Large-batch training empirically converges to sharp minima (high curvature, poor generalisation) while small-batch training finds flat minima. This is the "generalisation gap" (Keskar et al., 2016). (3) Gradient noise benefit: Small batches introduce beneficial noise that helps escape local minima. When scaling batch size, you must also scale the learning rate (linear scaling rule: LR ∝ batch size) and use warmup to stabilise early training.
ResNet skip connections — how is this principle used in Transformers?
They're already there — and considered essential. Every Transformer block uses residual connections: output of attention and FFN sublayers is added to their input (x + Sublayer(x)). The mathematical argument is identical to ResNet: gradient through the +x path has derivative 1, providing an unimpeded highway. Without residuals, a 100-layer Transformer would suffer shattered gradients. Pre-LN Transformers (LayerNorm before the sublayer, used in GPT-2+): x + Sublayer(LayerNorm(x)) vs Post-LN: LayerNorm(x + Sublayer(x)). Pre-LN trains more stably from scratch; Post-LN slightly better at convergence but requires careful warmup.
Explain the math behind the LSTM forget gate. What would happen if it was always stuck at 0 or 1?
Forget gate: f_t = σ(W_f·[h_{t-1}, x_t] + b_f), values in (0,1). Cell state: C_t = f_t ⊙ C_{t-1} + i_t ⊙ C̃_t. If f_t = 0 (fully forget): C_t = i_t ⊙ C̃_t — completely wipes memory each step, degenerating to a vanilla RNN with no long-term memory. If f_t = 1 (never forget): C_t = C_{t-1} + i_t ⊙ C̃_t — cell state only ever grows, accumulating information without forgetting. Over long sequences, cell state values grow unboundedly → saturate tanh → vanishing gradients again. The ideal: f_t near 1 for memories to preserve (e.g., subject's gender for pronoun agreement across a paragraph) and near 0 when transitioning to a new context.
Why is AdamW better than Adam + L2 regularisation for LLMs specifically?
In SGD, L2 regularisation and weight decay are mathematically identical. In Adam, they're not. Adding λ||W||²/2 to the loss makes the gradient g_t + λW. Adam divides this by √v̂_t — the weight decay term λW gets divided by the moving average of past gradients. Attention weights with large historical gradients (large v̂_t) get their weight decay throttled — they receive the least regularisation despite being the most likely to overfit. AdamW decouples weight decay: W ← W − α(m̂_t/(√v̂_t+ε)) − αλW. The λW term is outside the adaptive normalisation — every parameter experiences uniform decay. This single mathematical fix is what enabled training modern LLMs like GPT-3 and LLaMA without catastrophic memorisation of training data.
