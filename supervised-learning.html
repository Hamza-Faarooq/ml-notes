Chapter 1

The Anatomy of Supervised Learning

Before building any model, we need a common vocabulary. Every ML engineer and researcher communicates using the same notation. Memorize this — an interviewer will use these symbols without definition.

Symbol Name Meaning
\(x^{(i)}\)Input / FeaturesThe feature vector of the i-th training example (e.g., size of house, no. of bedrooms)
\(y^{(i)}\)Output / LabelThe target value we want to predict for the i-th example
\((x^{(i)}, y^{(i)})\)Training ExampleA single paired data point
\(m\)Dataset SizeTotal number of training examples
\(n\)Feature DimensionNumber of features in each example
\(\mathcal{H}\)Hypothesis SpaceThe set of all possible models we're searching through
\(h\)HypothesisOur learned model function: maps input \(x\) to predicted output \(\hat{y}\)
\(\theta\)Parameters / WeightsThe learned numbers that define our model

The Goal

Given a training set \(\{(x^{(1)}, y^{(1)}), \ldots, (x^{(m)}, y^{(m)})\}\), learn a function \(h : \mathcal{X} \to \mathcal{Y}\) such that \(h(x)\) is a "good" predictor for the corresponding value of \(y\).

🔑 Regression vs Classification

If \(y\) is continuous (e.g., house price = $450,000) → Regression problem
If \(y\) is discrete (e.g., spam/not-spam, cat/dog/bird) → Classification problem

Chapter 2

Linear Regression

Why it came up: We need the simplest possible way to draw a line (or hyperplane in higher dimensions) through data points to predict a continuous value. If you want to predict house price from square footage and bedrooms, a linear model is your first instinct.

The Hypothesis

We define our prediction as a weighted sum of the input features plus a bias term:

Linear Hypothesis \[ h_\theta(x) = \theta_0 + \theta_1 x_1 + \theta_2 x_2 + \cdots + \theta_n x_n \]

Here, \(\theta_i\) are the parameters (weights). \(\theta_0\) is the bias term (the y-intercept). To write this cleanly, we add a dummy feature \(x_0 = 1\), allowing:

Vector form \[ h_\theta(x) = \sum_{i=0}^{n} \theta_i x_i = \theta^T x \]

The Cost Function (Ordinary Least Squares)

How do we measure how "good" our parameters \(\theta\) are? We define the Cost Function \(J(\theta)\) as the average squared error between our predictions and the truth:

Mean Squared Error — the OLS Cost Function \[ J(\theta) = \frac{1}{2} \sum_{i=1}^{m} \left(h_\theta(x^{(i)}) - y^{(i)}\right)^2 \]
Why the \(\frac{1}{2}\) in front?
It's purely for mathematical convenience. When we differentiate the squared term, a factor of 2 comes down from the exponent. The \(\frac{1}{2}\) cancels it out, leaving cleaner update rules. It has zero effect on where the minimum lies — we're just scaling the function uniformly.
Why do we square the errors? Why not use absolute difference \(|h_\theta(x) - y|\)?
Two reasons: (1) Squaring makes the function differentiable everywhere — absolute value has a kink at zero where the derivative is undefined. (2) Probabilistically, squaring is the correct choice under Gaussian noise assumptions (proved in Chapter 5). Also, squaring penalizes large errors much more heavily than small ones, which is usually desirable.

Code: Linear Regression from Scratch

import numpy as np

# Data: housing size (sqft) → price ($1000s)
X = np.array([1000, 1500, 2000, 2500, 3000])
y = np.array([200, 280, 350, 430, 500])

# Add bias column (x_0 = 1)
X_b = np.c_[np.ones(len(X)), X]       # shape: (5, 2)
theta = np.zeros(2)                   # [theta_0, theta_1]

def cost(X_b, y, theta):
    m = len(y)
    predictions = X_b @ theta          # matrix multiply
    errors = predictions - y
    return (1 / (2 * m)) * np.dot(errors, errors)

def gradient(X_b, y, theta):
    m = len(y)
    predictions = X_b @ theta
    errors = predictions - y
    return (1 / m) * X_b.T @ errors     # shape: (2,)

# Gradient Descent
alpha = 1e-7
for i in range(10000):
    theta -= alpha * gradient(X_b, y, theta)

print(f"θ₀={theta[0]:.2f}, θ₁={theta[1]:.4f}")
print(f"Predict 2200 sqft: ${theta[0] + theta[1]*2200:.0f}k")python
Chapter 3

Gradient Descent — Walking Down the Hill

We have a cost function \(J(\theta)\) shaped like a bowl. We want to find the \(\theta\) at the bottom. Gradient Descent is an iterative algorithm that does this blindly but effectively — imagine being blindfolded on a hilly terrain, feeling the slope with your feet, and always stepping in the downhill direction.

The Update Rule

Gradient Descent Update (for each parameter j) \[ \theta_j := \theta_j - \alpha \frac{\partial}{\partial \theta_j} J(\theta) \]

The symbol \(:=\) means "update". The learning rate \(\alpha\) controls step size. All \(\theta_j\) are updated simultaneously at each step.

Full Derivation of the Update Rule

Let's derive the partial derivative for a single training example \((x, y)\):

  1. 1
    Start with the cost: \(\frac{\partial}{\partial \theta_j} J(\theta) = \frac{\partial}{\partial \theta_j} \frac{1}{2}(h_\theta(x) - y)^2\)
  2. 2
    Apply chain rule: \(= 2 \cdot \frac{1}{2}(h_\theta(x) - y) \cdot \frac{\partial}{\partial \theta_j}(h_\theta(x) - y)\)
  3. 3
    The derivative of the hypothesis: \(\frac{\partial}{\partial \theta_j}\left(\sum_i \theta_i x_i - y\right) = x_j\)
  4. 4
    Result: \(\frac{\partial}{\partial \theta_j} J(\theta) = (h_\theta(x) - y) \cdot x_j\)

Extending to all \(m\) training examples (Batch Gradient Descent):

Batch Gradient Descent Update Rule \[ \theta_j := \theta_j - \alpha \sum_{i=1}^{m} \left(h_\theta(x^{(i)}) - y^{(i)}\right) x_j^{(i)} \]

The Learning Rate \(\alpha\) — Physical and Mathematical Intuition

α Value What Happens Physically What Happens Mathematically Outcome
Too Small
e.g., 0.00001		 Tiny baby steps down the hill \(\alpha \nabla J(\theta)\) is microscopic. \(\theta\) barely moves each iteration. Training takes forever. May get permanently trapped in shallow local minima in non-convex landscapes.
Just Right
e.g., 0.01		 Confident steps early, slowing near the bottom Step size is large when gradient is steep, naturally shrinks as gradient approaches 0 near minimum. Converges smoothly to the global minimum.
Too Large
e.g., 1.5		 Leap from one side of the valley to the other, landing higher each time Update term \(\alpha \nabla J\) overshoots the minimum. Each step increases the error. Divergence. Loss approaches \(\infty\). You get NaN errors in code.

Chapter 4

The Normal Equation — The Analytical Solution

For linear regression specifically, because \(J(\theta)\) is a convex quadratic function (a perfect bowl), we don't have to iterate. We can use matrix calculus to jump directly to the exact minimum in one step by setting the gradient to zero.

Matrix Notation Setup

Represent the entire dataset as matrices:

  • \(\mathbf{X}\) is the Design Matrix — shape \(m \times (n+1)\). Each row is one training example \((x^{(i)})^T\).
  • \(\vec{y}\) is the Target Vector — shape \(m \times 1\). Column of all labels.
  • \(\theta\) is the Parameter Vector — shape \((n+1) \times 1\).

The cost function in matrix form:

Matrix form of J(θ) \[ J(\theta) = \frac{1}{2}(\mathbf{X}\theta - \vec{y})^T(\mathbf{X}\theta - \vec{y}) \]

Full Derivation: Where the Normal Equation Comes From

  1. 1
    Expand using transpose rule \((AB)^T = B^T A^T\): \[J(\theta) = \frac{1}{2}(\theta^T \mathbf{X}^T\mathbf{X}\theta - \theta^T \mathbf{X}^T \vec{y} - \vec{y}^T \mathbf{X}\theta + \vec{y}^T \vec{y})\]
  2. 2
    Simplify the middle terms: \(\theta^T \mathbf{X}^T \vec{y}\) and \(\vec{y}^T \mathbf{X}\theta\) are both scalars (single numbers). The transpose of a scalar equals itself. Therefore \(\vec{y}^T \mathbf{X}\theta = (\theta^T \mathbf{X}^T \vec{y})^T = \theta^T \mathbf{X}^T \vec{y}\). They're equal! Combine them: \[J(\theta) = \frac{1}{2}\left(\theta^T \mathbf{X}^T\mathbf{X}\theta - 2\theta^T \mathbf{X}^T \vec{y} + \vec{y}^T \vec{y}\right)\]
  3. 3
    Take gradient using two matrix calculus identities:
    Identity 1: \(\nabla_\theta(\theta^T A \theta) = 2A\theta\) (when \(A\) is symmetric, which \(\mathbf{X}^T\mathbf{X}\) is)
    Identity 2: \(\nabla_\theta(b^T \theta) = b\)

    Applying both: \[\nabla_\theta J(\theta) = \frac{1}{2}(2\mathbf{X}^T\mathbf{X}\theta - 2\mathbf{X}^T \vec{y}) = \mathbf{X}^T\mathbf{X}\theta - \mathbf{X}^T\vec{y}\]
  4. 4
    Set to zero and solve: \[\mathbf{X}^T\mathbf{X}\theta = \mathbf{X}^T\vec{y}\] Multiply both sides by \((\mathbf{X}^T\mathbf{X})^{-1}\): \[\boxed{\theta = (\mathbf{X}^T\mathbf{X})^{-1}\mathbf{X}^T\vec{y}}\]
🎯 Classic Interview Question

Q: If the Normal Equation gives the exact answer instantly, why do we ever use Gradient Descent?

A: "The Normal Equation requires computing the inverse of \(\mathbf{X}^T\mathbf{X}\), which is an \(n \times n\) matrix. Matrix inversion has time complexity \(O(n^3)\). If we have 100,000 features (common in NLP bag-of-words), that's \((10^5)^3 = 10^{15}\) operations — completely infeasible. Gradient Descent scales linearly with features at \(O(k \cdot n \cdot m)\), making it the only viable choice for high-dimensional data."

The Golden Rule:
  • If \(n < 10{,}000\) features → use the Normal Equation. Zero hyperparameter tuning, exact answer.
  • If \(n\) is large → use Gradient Descent.
  • For Logistic Regression → always use Gradient Descent (no closed-form solution exists).
# Normal Equation in NumPy
import numpy as np

X_b = np.c_[np.ones(m), X]   # add bias column

# One-shot solution: θ = (XᵀX)⁻¹ Xᵀy
theta_optimal = np.linalg.inv(X_b.T @ X_b) @ X_b.T @ y

# More numerically stable (uses least squares solver):
theta_optimal = np.linalg.lstsq(X_b, y, rcond=None)[0]python
Chapter 5

The Probabilistic Interpretation — Why Squared Errors?

This is where you separate yourself from average candidates. Anyone can memorize Least Squares. But why do we square the errors? The answer comes from Maximum Likelihood Estimation (MLE).

The Setup: Gaussian Noise Assumption

We assume the true relationship is linear, but our observations are corrupted by random noise \(\epsilon^{(i)}\):

\[ y^{(i)} = \theta^T x^{(i)} + \epsilon^{(i)} \]

We assume noise is IID (independently and identically distributed) Gaussian with mean 0 and variance \(\sigma^2\):

\[ \epsilon^{(i)} \sim \mathcal{N}(0, \sigma^2) \]

Therefore, the probability of observing \(y^{(i)}\) given \(x^{(i)}\) is:

Gaussian Likelihood \[ p(y^{(i)} \mid x^{(i)}; \theta) = \frac{1}{\sqrt{2\pi}\sigma} \exp\!\left(-\frac{(y^{(i)} - \theta^T x^{(i)})^2}{2\sigma^2}\right) \]

Maximum Likelihood Estimation

We want to find \(\theta\) that maximizes the probability of observing our entire dataset. This is the Likelihood Function:

\[ L(\theta) = \prod_{i=1}^{m} p(y^{(i)} \mid x^{(i)}; \theta) \]

Products are hard. We take the log-likelihood (log converts products to sums, and is monotonically increasing so maximizing \(\ell(\theta)\) is the same as maximizing \(L(\theta)\)):

Log-Likelihood \[ \ell(\theta) = m\log\frac{1}{\sqrt{2\pi}\sigma} - \frac{1}{2\sigma^2}\sum_{i=1}^{m}(y^{(i)} - \theta^T x^{(i)})^2 \]

To maximize \(\ell(\theta)\), we must minimize the subtracted term:

This is exactly the MSE cost function! \[ \frac{1}{2}\sum_{i=1}^{m}(y^{(i)} - \theta^T x^{(i)})^2 \equiv J(\theta) \]
💡 The "God Tier" Takeaway

Minimizing squared error is mathematically equivalent to Maximum Likelihood Estimation under Gaussian noise. The choice of \(\frac{1}{2}\sum(\hat{y} - y)^2\) isn't arbitrary — it's the statistically principled thing to do when you believe the data's randomness comes from a Gaussian distribution.

Chapter 6

Regularization — Fixing Overfitting

The Problem: If your model has too many features (or polynomial features like \(x_1^2, x_1^3\)), it will twist and bend to pass through every training point perfectly — training error of 0, but catastrophic failure on new data. This is Overfitting (High Variance).

Overfitted models have extremely large \(\theta\) values. Small changes in input cause massive output swings. The fix: penalize large weights.

L2 Regularization (Ridge Regression)

Add a penalty equal to the sum of squared weights:

Ridge Regression Cost \[ J(\theta) = \frac{1}{2m}\left[\sum_{i=1}^{m}(h_\theta(x^{(i)}) - y^{(i)})^2 + \lambda\sum_{j=1}^{n}\theta_j^2\right] \]
⚠️ Critical Detail

The penalty sum starts at j=1, not j=0. We never regularize the bias term \(\theta_0\). Penalizing the bias just shifts the model vertically — it doesn't prevent the model from curving wildly, which is what we actually care about.

\(\lambda\) (Lambda) — the regularization hyperparameter:

  • \(\lambda = 0\) → Standard linear regression (prone to overfitting)
  • \(\lambda \to \infty\) → All weights crushed to 0, model predicts the mean (underfitting)
  • Tune \(\lambda\) via cross-validation

Ridge: Modified Normal Equation

Ridge also fixes a mathematical flaw: \(\mathbf{X}^T\mathbf{X}\) can be singular (non-invertible) if:

  • You have more features than training examples (\(n > m\)) — the rank of \(\mathbf{X}^T\mathbf{X}\) is at most \(m\), so it can't be full rank
  • Features are perfectly correlated (multicollinearity) — duplicate columns make the determinant zero

Deriving the Ridge Normal Equation: write the regularization term as \(\lambda \theta^T L \theta\) where \(L\) is a modified identity matrix with a 0 in the top-left (to skip \(\theta_0\)):

\[ L = \begin{pmatrix} 0 & 0 & \cdots & 0 \\ 0 & 1 & \cdots & 0 \\ \vdots & & \ddots & \vdots \\ 0 & 0 & \cdots & 1 \end{pmatrix} \]

Taking the gradient and setting to zero yields:

Ridge Normal Equation \[ \theta = (\mathbf{X}^T\mathbf{X} + \lambda L)^{-1} \mathbf{X}^T \vec{y} \]
🔑 Why adding λL fixes singularity

If \(\mathbf{X}^T\mathbf{X}\) is singular, it has eigenvalues equal to 0. Adding \(\lambda L\) adds \(\lambda\) to each diagonal eigenvalue, shifting them from 0 to \(\lambda > 0\). A symmetric matrix with all positive eigenvalues is positive definite, which is guaranteed to be invertible. Ridge Regression literally forces the math to work.

L1 Regularization (Lasso Regression)

Instead of squaring the weights, take their absolute value:

Lasso Regression Cost \[ J(\theta) = \frac{1}{2m}\sum_{i=1}^{m}(h_\theta(x^{(i)}) - y^{(i)})^2 + \lambda\sum_{j=1}^{n}|\theta_j| \]

The crucial difference: Lasso is a Feature Selector. It forces weights of useless features to become exactly 0, producing sparse models.

The Geometry of L1 vs L2 — Why L1 Zeroes Things Out

Reframe regularization as constrained optimization. Minimizing \(J(\theta) + \lambda \cdot \text{Penalty}\) is mathematically equivalent to minimizing just \(J(\theta)\) subject to a budget constraint \(t\):

  • L2 constraint: \(\theta_1^2 + \theta_2^2 \leq t\) — This is a circle centered at the origin
  • L1 constraint: \(|\theta_1| + |\theta_2| \leq t\) — This is a diamond (rotated square)
💎 Interactive: L1 vs L2 Constraint Geometry

The ellipses are loss contours (equal loss curves) around the unregularized minimum ✦. The optimal regularized solution is where the smallest ellipse first touches the constraint boundary.

Why does L1 produce exact zeros?

The L1 diamond has sharp corners pointing along the coordinate axes. When the loss ellipses expand outward from the unconstrained minimum, they are overwhelmingly likely to first touch a corner of the diamond before touching a flat edge. At a corner, one coordinate is exactly 0 — that feature's weight is mathematically eliminated.

L2's circle has no corners — the ellipse gently kisses a random point on the smooth edge, leaving all weights non-zero but small.

⭐ Probabilistic "God Tier" Answer

Regularization isn't just engineering — it's Bayesian statistics:

  • L2 Ridge = Gaussian Prior on weights: \(P(\theta_j) \propto \exp(-\theta_j^2 / 2\tau^2)\). Assumes weights are normally distributed around zero.
  • L1 Lasso = Laplace Prior on weights: \(P(\theta_j) \propto \exp(-|\theta_j|/b)\). The Laplace distribution has a sharp spike at zero — that's why L1 drives weights to exactly zero.

Adding regularization = MAP (Maximum A Posteriori) estimation instead of MLE. The loss function = negative log-likelihood + negative log-prior.

# L2 Ridge Regression with sklearn
from sklearn.linear_model import Ridge, Lasso
from sklearn.preprocessing import StandardScaler

# Always scale features before regularization!
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X_train)

ridge = Ridge(alpha=1.0)   # alpha = λ in our notation
lasso = Lasso(alpha=0.1)

ridge.fit(X_scaled, y_train)
lasso.fit(X_scaled, y_train)

# L1 will zero out weak features
print("L2 weights:", ridge.coef_)   # all small but nonzero
print("L1 weights:", lasso.coef_)   # many exact zeros!python
Chapter 7

Logistic Regression — Classification

Now \(y\) is discrete. For binary classification: \(y \in \{0, 1\}\). We're predicting categories, not numbers.

Why Linear Regression Fails for Classification

  • The output \(\theta^T x\) can be any number from \(-\infty\) to \(+\infty\). A "spamminess score" of -450 or +12,000 is meaningless.
  • A single massive outlier data point will drag the decision boundary away from all normal data.
  • MSE on a binary target creates a non-convex loss with many local minima — gradient descent will get stuck.

The Sigmoid (Logistic) Function

We need a function that squashes any real number to \((0, 1)\):

Sigmoid Function \[ g(z) = \frac{1}{1 + e^{-z}} \]
📈 Interactive: The Sigmoid Function

As z→+∞, σ(z)→1. As z→−∞, σ(z)→0. At z=0, σ(0)=0.5. The output is always a valid probability.

The Logistic Hypothesis

Wrap our linear equation inside the sigmoid:

\[ h_\theta(x) = g(\theta^T x) = \frac{1}{1 + e^{-\theta^T x}} \]

Interpretation: \(h_\theta(x) = P(y=1 \mid x; \theta)\). If the output is 0.7, the model is 70% confident the example is class 1.

Decision Boundary

We predict \(y = 1\) if \(h_\theta(x) \geq 0.5\), else \(y = 0\).

Since \(g(z) \geq 0.5\) exactly when \(z \geq 0\), we predict \(y=1\) when \(\theta^T x \geq 0\).

The decision boundary is the surface \(\theta^T x = 0\) — the hyperplane separating the two classes in feature space.

The Log Loss (Cross-Entropy) Cost Function

⚠️ Interview Trap: Why not use MSE for Logistic Regression?

Plugging the sigmoid into MSE creates a non-convex function — full of local minima. Gradient descent will get stuck. We need a strictly convex loss function.

We use the Log Loss, which penalizes confident wrong answers infinitely:

Per-example Log Loss \[ \text{Cost}(h_\theta(x), y) = \begin{cases} -\log(h_\theta(x)) & \text{if } y = 1 \\ -\log(1 - h_\theta(x)) & \text{if } y = 0 \end{cases} \]

This compresses into one elegant formula:

Binary Cross-Entropy Loss \[ J(\theta) = -\frac{1}{m}\sum_{i=1}^{m}\left[y^{(i)}\log(h_\theta(x^{(i)})) + (1-y^{(i)})\log(1-h_\theta(x^{(i)}))\right] \]

Why Log Loss Makes Sense Intuitively

  • If \(y=1\) and model predicts 1.0: cost = \(-\log(1) = 0\) ✓ Perfect
  • If \(y=1\) but model predicts 0.001: cost = \(-\log(0.001) \approx 6.9\) — massive penalty for being confidently wrong
  • The \(-\log(x)\) curve shoots to infinity as \(x \to 0\) — ruthless exponential punishment for overconfident mistakes
🔑 Probabilistic Derivation

Log Loss is not arbitrary. Applying MLE to a Bernoulli distribution (the correct distribution for binary outcomes) derives this exact formula. It's statistically the principled choice.

Gradient Descent for Logistic Regression

After applying chain rule through the log and sigmoid (the complex terms cancel magnificently):

Gradient of Log Loss \[ \frac{\partial}{\partial \theta_j} J(\theta) = \frac{1}{m}\sum_{i=1}^{m}(h_\theta(x^{(i)}) - y^{(i)})x_j^{(i)} \]
⭐ The Update Rule is the Same!

This is identical in form to linear regression's update rule. The algorithm looks the same in code. The only difference is the definition of \(h_\theta(x)\): linear uses \(\theta^T x\), logistic uses \(\frac{1}{1+e^{-\theta^T x}}\).

import numpy as np

def sigmoid(z):
    return 1 / (1 + np.exp(-z))

def logistic_cost(X, y, theta):
    m = len(y)
    h = sigmoid(X @ theta)
    # Clip to avoid log(0)
    h = np.clip(h, 1e-10, 1-1e-10)
    return -(1/m) * (y @ np.log(h) + (1-y) @ np.log(1-h))

def logistic_gradient(X, y, theta):
    m = len(y)
    h = sigmoid(X @ theta)
    return (1/m) * X.T @ (h - y)

# Gradient descent loop
theta = np.zeros(X.shape[1])
alpha, iters = 0.1, 1000
for _ in range(iters):
    theta -= alpha * logistic_gradient(X_b, y, theta)

# Prediction: apply sigmoid, threshold at 0.5

Chapters 13–14

Generalized Linear Models (GLMs) & Softmax

Linear Regression and Logistic Regression aren't just two unrelated algorithms. They are two specific instances of one unified mathematical framework called Generalized Linear Models (GLMs).

The Exponential Family

A distribution belongs to the Exponential Family if it can be written as:

Exponential Family Form \[ p(y; \eta) = b(y)\exp(\eta^T T(y) - a(\eta)) \]
  • \(\eta\) — Natural parameter (what we learn)
  • \(T(y)\) — Sufficient statistic (usually \(T(y) = y\))
  • \(a(\eta)\) — Log partition function (normalization constant)
  • \(b(y)\) — Base measure

The Three GLM Assumptions

  1. \(y \mid x; \theta \sim \text{ExponentialFamily}(\eta)\)
  2. Goal: predict \(E[y \mid x]\), so \(h_\theta(x) = E[y \mid x]\)
  3. The natural parameter is linear: \(\eta = \theta^T x\)

Softmax Regression (Multi-Class Classification)

For \(k\) classes (\(y \in \{1, \ldots, k\}\)), we use the Multinomial distribution. Each class gets its own weight vector \(\theta_j\). The Softmax function converts raw scores to probabilities:

Softmax Function \[ P(y=j \mid x; \theta) = \frac{e^{\theta_j^T x}}{\sum_{l=1}^{k} e^{\theta_l^T x}} \]

Why exponentials?

  • Ensures all probabilities are strictly positive (since \(e^z > 0\) always)
  • The denominator normalizes so probabilities sum to 1
  • Disproportionately rewards the largest score — acts like a "soft" argmax
🎯 Interview: Relation to Binary Logistic

For \(k=2\), Softmax reduces exactly to Logistic Regression. They're the same algorithm — Softmax is the generalization.

def softmax(z):
    # z: (m, k) matrix of raw scores
    exp_z = np.exp(z - z.max(axis=1, keepdims=True))  # numerical stability
    return exp_z / exp_z.sum(axis=1, keepdims=True)

# Cross-entropy loss for multi-class
def cross_entropy_loss(probs, y_onehot):
    # probs: (m, k), y_onehot: (m, k)
    m = len(y_onehot)
    return -np.sum(y_onehot * np.log(probs + 1e-10)) / mpython
Chapter 15

GLM Proofs — Deriving Algorithms from Distributions

The "God Tier" skill: proving that plugging a distribution into the GLM framework automatically derives the algorithm. All three proofs use the same trick: \(x = \exp(\log x)\).

Proof 1: Gaussian → Linear Regression

Gaussian PDF: \(p(y; \mu) = \frac{1}{\sqrt{2\pi}}\exp\!\left(-\frac{1}{2}(y - \mu)^2\right)\)

Expand and separate: \(p(y;\mu) = \underbrace{\frac{1}{\sqrt{2\pi}}e^{-y^2/2}}_{b(y)} \cdot \exp\!\left(\mu y - \frac{\mu^2}{2}\right)\)

Extraction: \(\eta = \mu\), so \(h_\theta(x) = E[y] = \mu = \eta = \theta^T x\). ✓ Linear Regression.

Proof 2: Bernoulli → Logistic Regression

Bernoulli PMF: \(p(y;\phi) = \phi^y(1-\phi)^{1-y}\)

Apply \(\exp(\log(\cdot))\) and expand:

\[ p(y;\phi) = \exp\!\left(y\log\frac{\phi}{1-\phi} + \log(1-\phi)\right) \]

Extraction: \(\eta = \log\!\left(\frac{\phi}{1-\phi}\right)\) (the log-odds / logit).

Invert to get \(\phi\):

\[ e^\eta = \frac{\phi}{1-\phi} \implies \phi = \frac{e^\eta}{1+e^\eta} = \frac{1}{1+e^{-\eta}} \]

Since \(\eta = \theta^T x\): \(h_\theta(x) = \frac{1}{1+e^{-\theta^T x}}\). ✓ Sigmoid / Logistic Regression.

Proof 3: Poisson → Poisson Regression

For count data (number of events). Poisson PMF: \(p(y;\lambda) = \frac{\lambda^y e^{-\lambda}}{y!}\)

Rewrite: \(p(y;\lambda) = \frac{1}{y!}\exp(y\log\lambda - \lambda)\)

Extraction: \(\eta = \log\lambda \implies \lambda = e^\eta\).

Therefore: \(h_\theta(x) = e^{\theta^T x}\). ✓ Poisson Regression (exponential hypothesis, guarantees positive predictions).

⭐ The Unifying Pattern

In all cases: (1) Write the distribution in exponential family form, (2) Extract \(\eta\), (3) Invert to find the mean, (4) Substitute \(\eta = \theta^T x\). The resulting function is your model's hypothesis.

Chapters 17–22

KL Divergence — The Engine Behind Modern AI

KL Divergence is hiding inside almost every ML algorithm you'll encounter. Cross-entropy loss in classification, the VAE loss, RLHF in ChatGPT, t-SNE visualizations — all are fundamentally minimizing KL Divergence.

The Formula

KL Divergence from Q to P \[ D_{KL}(P \| Q) = \sum_x P(x) \log\frac{P(x)}{Q(x)} \]

\(P\) = True distribution (reality), \(Q\) = Model's predicted distribution (approximation). Measures the "inefficiency" of using \(Q\) when the truth is \(P\).

The Asymmetry Trap (Always Asked in Interviews)

🎯 "Is KL Divergence a distance metric?"

No. A true distance metric must be symmetric: \(d(A,B) = d(B,A)\). KL Divergence is asymmetric: \(D_{KL}(P\|Q) \neq D_{KL}(Q\|P)\). They have completely different denominators and trigger their penalties in opposite scenarios.

The Camel Analogy: Forward vs Reverse KL

Imagine the true data distribution \(P\) looks like a two-humped camel (bimodal). Your model \(Q\) is a simple single bell curve. Where does it put its hump?

TypeFormulaBehaviorNicknameUsed In
Forward KL \(D_{KL}(P\|Q)\) \(\sum P\log(P/Q)\) If \(P\) is high, \(Q\) must be high (or penalty → ∞). Q spreads wide to cover all humps. Lands in the valley between them. Mean-Seeking / Zero-Avoiding Classification (cross-entropy)
Reverse KL \(D_{KL}(Q\|P)\) \(\sum Q\log(Q/P)\) If \(Q\) is high, \(P\) must be high. Q shrinks to hide inside one safe hump and ignores the rest. Mode-Seeking / Zero-Forcing Variational Inference, VAEs, RLHF

Cross-Entropy is Just Forward KL

Expand KL Divergence:

\[ D_{KL}(P\|Q) = \underbrace{-\sum P(x)\log P(x)}_{H(P) = \text{const}} - \underbrace{\sum P(x)\log Q(x)}_{-H(P,Q)} \]

Since \(H(P)\) is fixed (the true labels don't change during training), minimizing \(D_{KL}(P\|Q)\) is identical to minimizing Cross-Entropy \(H(P,Q)\). That's why we use cross-entropy in code — it's the same objective with the constant dropped.

Where KL Divergence Powers Production Systems

  • Every Classification Model (via cross-entropy) — Forward KL under the hood
  • ChatGPT / RLHF (PPO) — KL penalty between "new polite model" and "original base model" prevents catastrophic forgetting
  • Variational Autoencoders — Forces latent space to match a standard Normal distribution (Reverse KL / ELBO)
  • t-SNE — Minimizes KL between high-dimensional neighbor probabilities and 2D neighbor probabilities
  • Decision Tree Information Gain — Literally KL divergence between class distributions before/after a split

Generative Learning Algorithms

Discriminative vs Generative: The Key Divide

ApproachWhat it learnsAnalogyExamples
Discriminative \(P(y|x)\) — given features, what's the class? Learns to spot the letter "ç" to distinguish French vs English. Doesn't understand either language. Logistic Regression, SVM, Neural Networks
Generative \(P(x|y)\) and \(P(y)\) — what do the features look like for each class? Actually learns to speak fluent French and fluent English, then picks whichever fits better. GDA, Naive Bayes, GANs, VAEs

Prediction via Bayes' Theorem: \(P(y|x) = \frac{P(x|y)P(y)}{P(x)}\)

Gaussian Discriminant Analysis (GDA)

For continuous features, we model each class as a multivariate Gaussian. The Multivariate Gaussian PDF:

Multivariate Gaussian \[ P(x; \mu, \Sigma) = \frac{1}{(2\pi)^{n/2}|\Sigma|^{1/2}} \exp\!\left(-\frac{1}{2}(x-\mu)^T\Sigma^{-1}(x-\mu)\right) \]
  • \(\mu \in \mathbb{R}^n\) — Mean vector (center of the bell curve)
  • \(\Sigma \in \mathbb{R}^{n \times n}\) — Covariance matrix (shape/spread of the bell curve)

GDA Model Assumptions

  • \(y \sim \text{Bernoulli}(\phi)\)
  • \(x \mid y=0 \sim \mathcal{N}(\mu_0, \Sigma)\)
  • \(x \mid y=1 \sim \mathcal{N}(\mu_1, \Sigma)\)
⚠️ Interview Trap: Shared Covariance Matrix

Both classes share the same \(\Sigma\). This forces both Gaussians to have the same shape (just different centers). Mathematically, this guarantees a linear decision boundary. If you give each class its own \(\Sigma\), you get Quadratic Discriminant Analysis (QDA) with a curved boundary.

MLE Parameters (Closed-Form Solutions)

  • \(\phi = \frac{1}{m}\sum_{i=1}^m \mathbf{1}\{y^{(i)}=1\}\) — fraction of positive examples
  • \(\mu_0 = \frac{\sum \mathbf{1}\{y^{(i)}=0\} x^{(i)}}{\sum \mathbf{1}\{y^{(i)}=0\}}\) — mean of class 0 examples
  • \(\mu_1 = \frac{\sum \mathbf{1}\{y^{(i)}=1\} x^{(i)}}{\sum \mathbf{1}\{y^{(i)}=1\}}\) — mean of class 1 examples
  • \(\Sigma = \frac{1}{m}\sum_{i=1}^m (x^{(i)} - \mu_{y^{(i)}})(x^{(i)} - \mu_{y^{(i)}})^T\) — pooled covariance
🎯 GDA vs Logistic Regression (Classic CS229 Question)

If you train a GDA model and compute \(P(y=1|x)\) via Bayes, it mathematically simplifies to the sigmoid: \(\frac{1}{1+e^{-\theta^T x}}\). Both give the same form of decision boundary! So which do you use?

  • GDA makes stronger assumptions (Gaussian data). If data truly is Gaussian, GDA is more efficient — needs less data to find the optimal boundary.
  • Logistic Regression is more robust. Doesn't assume Gaussianity. Works on skewed, Poisson, or messy real-world data.
  • Gaussian \(\Rightarrow\) Logistic. But Logistic \(\not\Rightarrow\) Gaussian. Logistic is more universally applicable.

Naive Bayes (Generative Model for Text)

For discrete features (word counts), we need Naive Bayes. With a 50,000-word vocabulary, modeling all word combinations directly requires \(2^{50000}\) parameters — physically impossible.

The Naive Independence Assumption

Assume words are conditionally independent given the class:

\[ P(x_1, x_2, \ldots, x_n | y) = \prod_{i=1}^{n} P(x_i | y) \]

This collapses the intractable joint distribution into simple per-word counts. (It's "naive" because words aren't truly independent — "Nigerian Prince" are highly correlated. But it works remarkably well anyway.)

Laplace Smoothing (The Zero Probability Fix)

The fatal flaw: If a word never appeared in training data, its probability is 0. Any product containing a 0 is 0 — the model crashes with a 0/0 error on any unseen word.

Fix: Add pseudocounts. For a feature with \(k\) possible values:

Laplace Smoothed Probability \[ P(x_j = v \mid y = 1) = \frac{\text{count}(x_j = v \text{ in class 1}) + 1}{\text{count(class 1 examples)} + k} \]

Adding 1 to numerator and \(k\) to denominator guarantees no zero probability, while becoming negligible when data is plentiful.

Support Vector Machines — The Max-Margin Classifier

Logistic Regression draws a boundary. SVMs find the best possible boundary — the one with the maximum margin between classes. Out of infinite valid separating hyperplanes, SVMs pick the one that is as far as possible from both sides.

Building the "Street"

The decision boundary is the midline of a "street." We define three parallel lines:

\[ w^T x + b = 0 \quad \text{(decision boundary)} \] \[ w^T x + b = +1 \quad \text{(positive gutter)} \] \[ w^T x + b = -1 \quad \text{(negative gutter)} \]

Points on the gutters are called Support Vectors — they physically hold the street up. Remove all other points and the boundary doesn't move.

Width of the Street

Using vector projection, the street width is \(\frac{2}{\|w\|}\). Maximizing \(\frac{2}{\|w\|}\) is equivalent to minimizing \(\frac{1}{2}\|w\|^2\).

The Primal Optimization Problem

SVM Primal Form \[ \text{Minimize} \quad \frac{1}{2}\|w\|^2 \] \[ \text{Subject to} \quad y^{(i)}(w^T x^{(i)} + b) \geq 1 \quad \forall i \]

The Dual Form — Why We Flip the Math

The primal form has \(n\)-dimensional weight vector \(w\). For high-dimensional data, this is expensive. Using Lagrangian multipliers \(\alpha_i\), we convert to the Dual Form where \(w\) disappears and only dot products of input pairs remain:

SVM Dual Objective \[ \max_\alpha \sum_{i=1}^m \alpha_i - \frac{1}{2}\sum_{i=1}^m\sum_{j=1}^m y^{(i)}y^{(j)}\alpha_i\alpha_j \langle x^{(i)}, x^{(j)} \rangle \] \[ \text{s.t.} \quad \alpha_i \geq 0, \quad \sum_i \alpha_i y^{(i)} = 0 \]
⭐ The Critical Insight

The entire optimization only depends on dot products \(\langle x^{(i)}, x^{(j)} \rangle\) between pairs of training points. It doesn't care about the actual feature values — only the similarity scores between examples. This opens the door to the Kernel Trick.

The Kernel Trick — Infinite Dimensions for Free

The Problem: Data isn't always linearly separable (e.g., concentric circles). We could project data into higher dimensions where it becomes separable — but computing dot products in a million-dimensional space would crash any machine.

The Insight: The Dual Form only needs the dot product result, not the individual high-dimensional vectors. Can we compute \(\phi(x_i)^T\phi(x_j)\) without ever computing \(\phi(x_i)\)?

Algebraic Proof (The Polynomial Kernel)

For 2D vectors \(x = [x_1, x_2]^T\), \(z = [z_1, z_2]^T\), define mapping \(\phi(x) = [x_1^2, \sqrt{2}x_1x_2, x_2^2]^T\).

Hard way (explicit projection): \(\phi(x)^T\phi(z) = x_1^2z_1^2 + 2x_1z_1x_2z_2 + x_2^2z_2^2\)

Kernel shortcut: \(K(x,z) = (x^Tz)^2 = (x_1z_1 + x_2z_2)^2 = x_1^2z_1^2 + 2x_1z_1x_2z_2 + x_2^2z_2^2\)

They're identical. Four operations instead of eleven. The saving scales enormously with dimension.

The Two Most Important Kernels

KernelFormulaEquivalent ProjectionWhen to Use
Polynomial \(K(x,z) = (x^Tz + c)^d\) All polynomial features up to degree \(d\) Text classification, data with polynomial relationships
RBF / Gaussian \(K(x,z) = \exp\!\left(-\frac{\|x-z\|^2}{2\sigma^2}\right)\) Infinite-dimensional feature space (via Taylor series of \(e^x\)) Non-linear boundaries, most common default choice
🔑 RBF as a Proximity Sensor

The RBF kernel measures closeness: if \(x\) and \(z\) are identical, distance is 0, \(\exp(0) = 1\) (maximum similarity). If they're far apart, the exponential approaches 0 (no similarity). Via Taylor expansion of \(e^x\), this computes the dot product of infinite-dimensional vectors.

🔵 Interactive: SVM Margin Visualization

The highlighted points on the margin boundaries are the support vectors — the only points that matter for defining the hyperplane.

Chapters 34–38

Tree-Based Models & Ensemble Methods

If SVMs are the kings of mathematical elegance, tree ensembles are the kings of real-world production. For tabular data (CSV files, database tables), gradient boosting consistently wins. Suggesting SVMs or deep learning before tree ensembles for tabular data is a red flag in an interview.

Decision Trees

Instead of a continuous boundary, decision trees ask a sequence of yes/no questions, carving the feature space into rectangular boxes. At each node, they greedily pick the split that makes the child boxes most pure (one-class).

Measuring Impurity: Entropy vs Gini

Entropy (Information-Theoretic) \[ H(S) = -\sum_{i=1}^k p_i \log_2 p_i \]
Gini Impurity (Default in scikit-learn) \[ \text{Gini}(S) = 1 - \sum_{i=1}^k p_i^2 \]

Both range from 0 (pure) to maximum when classes are equally mixed. Gini avoids log computation — faster in practice.

Information Gain

\[ \text{IG} = H(\text{parent}) - \frac{|L|}{|S|}H(\text{left child}) - \frac{|R|}{|S|}H(\text{right child}) \]

Pick the split that maximizes Information Gain at each node.

⚠️ The Fatal Flaw of Single Trees

A fully grown tree will create a tiny box around each individual training point. Training error = 0%, but test error is catastrophic. Changing one data point can cascade and completely restructure the entire tree (high variance / overfitting). Fix: use an ensemble.

Random Forests (Bagging)

Statistical motivation: If you average \(N\) independent random variables each with variance \(\sigma^2\), the variance of their average is \(\sigma^2/N\). Build 100+ trees and average them — variance collapses toward zero.

Making Trees Independent (The "Random" Part)

  1. Bootstrap Sampling (Bagging): Each tree gets a random sample with replacement of the training data. ~63% of data is used per tree; the rest are "out-of-bag" samples (can be used as free validation).
  2. Feature Randomness: At each split, only a random subset of \(\sqrt{\text{total features}}\) features is considered. This prevents the strongest feature from dominating every tree, forcing them to learn diverse patterns.

Gradient Boosting (Sequential Error Correction)

Random forests build trees in parallel independently. Boosting builds them sequentially, each one learning from the previous one's mistakes.

  1. 1
    Build Tree 1. It makes predictions \(\hat{y}\).
  2. 2
    Compute residuals: \(r_i = y_i - \hat{y}_i\)
  3. 3
    Build Tree 2 to predict these residuals (not the original target)
  4. 4
    Update: \(\hat{y}_{\text{new}} = \hat{y}_{\text{old}} + \alpha \cdot \text{Tree}_2(x)\)
  5. 5
    Repeat for Tree 3, 4, ..., N

Final prediction = sum of all tree predictions (each scaled by learning rate \(\alpha\)):

\[ F(x) = F_0(x) + \alpha f_1(x) + \alpha f_2(x) + \cdots + \alpha f_N(x) \]

XGBoost — Why It Wins Kaggle

XGBoost is a mathematically rigorous version of gradient boosting. Standard GBM uses the first-order Taylor approximation of the loss. XGBoost uses the second-order (quadratic) Taylor approximation:

2nd-Order Taylor Expansion of Loss \[ L(y, F_{t-1} + f_t) \approx L(y, F_{t-1}) + g_i f_t + \frac{1}{2}h_i f_t^2 \]

Where \(g_i = \frac{\partial L}{\partial F_{t-1}}\) (gradient) and \(h_i = \frac{\partial^2 L}{\partial F_{t-1}^2}\) (Hessian — second derivative).

Setting derivative to zero (Newton's Method) gives the optimal leaf weight in one step:

XGBoost Optimal Leaf Weight \[ w^* = -\frac{\sum_i g_i}{\sum_i h_i + \lambda} \]
🎯 "Why is XGBoost better than standard GBM?"

Three reasons:
1. 2nd-order optimization: Uses Hessian for curvature information. Like Newton-Raphson vs plain gradient descent — converges in far fewer trees.
2. Adaptive step size: Large Hessian (steep curvature) → small step; flat curvature → large step. Self-regulating.
3. Built-in L1/L2 regularization: \(\lambda\) in the leaf weight formula directly prevents overfitting at the tree-building stage.

K-Nearest Neighbors — Lazy Learning

KNN is a non-parametric, instance-based algorithm. It stores the entire training dataset and makes predictions at query time by looking up the nearest neighbors.

Eager Learners (LR, SVM, Trees)KNN (Lazy Learner)
TrainingHeavy computation (gradient descent, optimization)\(O(1)\) — just save the dataset
PredictionFast — formula evaluation\(O(N \cdot d)\) — compute distances to all N points
MemoryStores only weightsStores entire dataset

The Distance Metric (Minkowski)

Minkowski Distance \[ D(x, z) = \left(\sum_{i=1}^{d} |x_i - z_i|^p\right)^{1/p} \]
  • \(p=1\) → Manhattan Distance (L1 norm) — grid-walking, robust in high dimensions
  • \(p=2\) → Euclidean Distance (L2 norm) — straight-line, standard default
⚠️ The Standardization Trap

Q: Your KNN for house price prediction fails miserably. Why?

A: Features have different scales: square footage ranges 500–5000, bedrooms range 1–5. The distance formula treats all numbers equally, so the large-scale "square footage" feature completely dominates the distance calculation — bedrooms become irrelevant. Always normalize/standardize features before using KNN.

Choosing K: The Bias-Variance Tradeoff

🔍 Interactive: KNN — Effect of K Value

K=1: Jagged islands, overfitting. High K: Smooth boundary, underfitting. Find the sweet spot via cross-validation.

KVarianceBiasBoundary ShapeEffect
K = 1Very HighVery LowJagged, irregularMemorizes noise, creates "islands" around outliers
K = 5–15ModerateModerateSmooth, generalizedGood balance — start here, tune with CV
K = N (all data)ZeroMaximumFlat linePredicts majority class regardless of input

The Odd K Rule

For binary classification, always choose odd K to avoid ties. For multi-class (\(k=3\) classes, \(K=3\) neighbors), ties can still occur — fix with Distance-Weighted Voting: each neighbor votes with weight \(1/d\) (inverse distance). The nearest neighbor counts more.

KNN Regression

For continuous targets, simply take the mean of the K nearest neighbors' values (instead of majority vote).

⚠️ KNN Regression Cannot Extrapolate

If the most expensive house in training data is $1M, KNN can never predict >$1M — it just averages the highest nearby values. Linear regression can extrapolate indefinitely along its line. This is a fundamental limitation of instance-based methods.

Quick Reference

CDC Interview Rapid-Fire Answers

What's the difference between Lasso and Ridge regularization?
Ridge (L2) adds \(\lambda\sum\theta_j^2\) — shrinks all weights proportionally toward zero but rarely reaches exactly zero. Lasso (L1) adds \(\lambda\sum|\theta_j|\) — its diamond-shaped constraint region has corners on the axes, so the loss contours are likely to hit a corner first, zeroing out weak features entirely. L1 = automatic feature selection. Probabilistically, L2 = Gaussian prior on weights, L1 = Laplace prior.
Why does XGBoost outperform standard Gradient Boosting?
Three reasons: (1) 2nd-order Taylor expansion — uses the Hessian for curvature info, jumping to the optimal leaf weight analytically in one step (Newton's method vs gradient descent). (2) Built-in L1/L2 regularization — the optimal leaf weight formula is \(-\frac{\sum g_i}{\sum h_i + \lambda}\), directly penalizing large leaf weights. (3) Adaptive step sizing — large Hessian automatically produces smaller steps; flat curvature allows larger jumps.
What is the Kernel Trick?
SVMs in Dual Form only need dot products between training examples, not the actual feature vectors. The Kernel Trick is a function K(x,z) that computes the dot product in a high-dimensional projected space without ever explicitly computing the projection. Example: K(x,z) = (xᵀz)² produces the same result as computing explicit 3D polynomial features and dotting them — but requires 4 operations instead of 11. The RBF kernel implicitly projects into infinite dimensions via the Taylor expansion of e^x.
Why can't we use MSE for Logistic Regression?
Plugging the sigmoid into MSE creates a non-convex cost function — it has multiple local minima. Gradient descent will get stuck in the wrong valley. Log Loss (Cross-Entropy) is strictly convex when combined with the sigmoid, guaranteeing gradient descent finds the global minimum. Additionally, Log Loss is the statistically principled choice — it's MLE under a Bernoulli distribution assumption.
Why does GDA give a linear boundary even though it models Gaussians?
Because both classes share the same covariance matrix Σ. Two Gaussian "bowls" with identical shapes (same Σ) but different centers (μ₀, μ₁) will intersect along a flat plane — a linear boundary. If each class has its own Σ, the surfaces have different orientations and their intersection is a quadratic curve (Quadratic Discriminant Analysis).
What makes Random Forests different from just training multiple decision trees?
Without randomness, all trees would train on the same data and find the same splits — averaging them does nothing. Random Forests introduce two independence mechanisms: (1) Bootstrap sampling — each tree trains on a random sample with replacement (~63% of data), (2) Feature randomness — at each split, only √n_features are available to split on. This forces trees to learn different patterns. The variance-reduction effect requires independence, which these techniques provide.
